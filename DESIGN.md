# DESIGN — Bros

## Visual

- Dark surface with cool blue/teal accents (`--bros-accent`, `--bros-accent-2`)
- Boot overlay covers the app only while this process is still autostarting services: `#0f1419` panel, Lucide spinner while a service is starting, check when it is running, alert on error
- Thin themed scrollbars (≈6px, muted thumb, no arrows) for page content. Dock Previous chats and Docs tree scroll with hidden bars + recents chevron hints; Dashboard…Status never scroll
- Shared shell; same chrome in app and website; only nav links differ
- Docs markdown and Chat assistant and user bodies use the same prose styles, so headings, lists, code, tables, and blockquotes match Docs inside the thread and bubbles. Fenced snippets have a copy control.
- Docs site landing vs app dashboard: same theme, different homepage (the website owns marketing `/`; app `/` is the dashboard)
- Docs site local: http://127.0.0.1:3056/bros/ (`baseURL` `/bros/`)

## Navigation

- **Desktop (lg+):** left dock column in the app frame. Main content sits beside it (flex); the panel occupies layout width so content shrinks/grows. Resizable by dragging the right edge. Persist `open` / `width` / `iconMode` in localStorage. Drag below 80px snaps to icon-only (icons + hover titles); drag past 112px snaps labels back. Icon-only active/hover highlight is a compact box around the glyph, not a full-rail bar that covers the icon. One brand (dock when open; top bar brand + panel toggle only when dock closed).
- **Mobile:** hamburger overlay drawer. No dock column; overlay is OK.
- App order: Dashboard, New chat (`/chat`), Providers, Sidecars, Terminal (`/terminal`), Desktop (`/desktop`), Status (fixed height, no scroll), divider, Previous chats (links go to `/chat/:id`), divider, pinned sidecar UIs, divider, Docs (collapsible directory tree of every `/docs` page, own hidden scrollbar) + Settings, footer GitHub: https://github.com/jasenmichael/bros
- `/chat` is the only conversation page. A provider and a model sit in the tools row. Chat is one completion.
- `/chat` is a new empty conversation: full-height column, centered greeting + rounded composer. Provider then model sit left in a compact tools row above the composer, context size on the right — not a fat header card or empty message well. The provider trigger stays as wide as the longest option (`Ollama (host port:11434)`), not the selected label — picking Groq or Gemini does not shrink it. The menu matches that width so full Ollama labels stay visible. The model trigger stays compact; the open menu is wider so full Ollama names (`freehuntx/qwen3-coder:14b`) are not truncated. Ellipsis on either picker only when the viewport is too narrow. The Message composer stays the full tools-row width, not the provider trigger width. `/chat/:id` (and the first send on `/chat`) fills the column with turns; composer docks to the bottom; only the message thread scrolls (not the app frame). Opening a saved thread pins that scroller to the latest turn after render. Recents live in the dock, not a Chat left rail. Each recent has a ⋮ menu: Rename, Delete. While waiting: centered muted **thinking… 1.2s** plus compact **Stop**. Send stays the arrow, disabled until the stream ends. Composer stays editable. After tokens start, **Stop** sits on the live assistant meta line. A round **Voice to text** mic sits left of Send/Stop (same pill radius); recording pulses the accent and does not auto-send. Assistant meta sits under the body: role+model left, `1.4s · 128 tok` right when stored, plus a copy icon for the stored raw markdown.
- Docs site: Home, then the same collapsible docs tree (Start, App, Sidecars, Contribute, API)
- Docs pages: breadcrumbs above the title, walked from that tree
- Sidecar web UIs with `navPinned` appear below a divider (no Pinned heading) only while that sidecar is running and not disabled (a stored pin stays; the dock ignores it while the sidecar is disabled or stopped). LAN pins are `http://127.0.0.1:<publish>/`, or `http://127.0.0.1:<publish>/${id}/` when `proxy.public` and the UI listens under that path. Via-tunnel pins for `proxy.public` webuis are same-host `/${id}/`. No shipped pack opts in today (OpenCode LAN is `http://127.0.0.1:4097/`). Pin in nav is only on cards with a published `webui`. A package web UI pin uses the same dock rule and hides while the app is disabled, Desktop is down, or its service is stopped. Published APIs keep Open, not Pin.

## Pages

- `/` — website: marketing landing. App: fixed dashboard hub (Chats, Providers, Sidecars, Tunnel). No widget add/remove/reorder. Shell renders before `GET /api/dashboard/summary`; panels show Loading… until that returns. Chats lists recent threads plus New chat. Providers lists Ollama, host Ollama when enabled, and other Chat-on providers, plus active pulls. Sidecars lists phase and Open on a running web UI. Tunnel keeps the host cloudflared toggle and links to `/status`. An attention row appears only when Docker, a sidecar, Ollama, disk, or chat readiness needs a person. No full Status table, container list, GPU, API paths, CLI commands, or provider URLs on Home
- `/status` — detail: Bros app, Docker, disk, GPU, host Tunnel, **Bros services** (grouped container inventory; not on Home), each sidecar port/state/error, autostart/pin, logs links. No Start/Stop/Restart on Core Ollama or Whisper. Whisper enable lives on Settings. Recovery uses a toast, not a custom snackbar.
- `/docs`, `/docs/*` — identical docs-layer pages in website and app (theme layout + prose)
- `/chat`, `/chat/:id`, `/providers`, `/sidecars`, `/sidecars/:id/logs`, `/settings` — app-only. Settings is a compact page: Chat (two full-width textareas + Save), Whisper switch (off by default; on pulls images then starts the sidecar), Host Ollama switch (off by default), MCP servers (stored; Chat does not call them), read-only paths, Repair data dir (confirm shows `BROS_HOST_UID`, `BROS_HOST_GID`, and the chown command), proxy key and tunnel API URLs, then full-width passkey inputs. `/desktop` is the stream. The Drawer sits at the bottom and shows on hover or touch. It lists running apps, pinned launchers, and the library icon. A mark means a window is mapped. The library is a searchable grid. Its settings control sits at the bottom right and opens the Apps board. `/settings/desktop` is Desktop settings: an Apps board of package gui tiles, then Check, Update, services, Rebuild, and Add app. A version sits beside the label when Desktop reports one, and on a GUI card in the Apps board. Check stays on the settings row except for a run app. Update shows only after Check finds a newer version, and for node that version is the pin. Check and Update spin on that row and can run together. A run app has no Check. Its Update rebuilds Desktop. Several run apps can be added, then one Rebuild installs those layers and swaps the container. The toast stays up while the image builds, then reports the swap or the failure. An addon row has Disable. An enabled package app with a services command has Start, Stop, Restart, and Logs. A package web UI row has Forward to host and Pin in nav. Logs opens `/settings/desktop/:id/logs`. A bottom-left toast shows ensure progress on every page and closes when the queue finishes. A failure is its own toast. Sidecars page is one list. Add sidecar and From a repo sit on their own row above the filters. Filters are three segmented controls on one line: All / Running / Stopped, interface type (All / webui / api / openapi / cli / gui), and Core / Addon / Custom. Each group uses the same bordered button control and stays content-width. Core (Ollama, Desktop, Whisper) has no Start/Stop/Restart/Autostart. Addon and custom (shipped OpenCode / Open WebUI / Firecrawl / Firecrawl UI / OpenJEV / Pi / Cursor plus packs in `lib/sidecars/custom` and git clones) stay stopped until Autostart is on. Only `lib/sidecars/custom/README.md` is tracked. A custom pack can later move to addon or core. An addon can later move to core. Each card has a refresh icon next to running/stopped. Each card heading is the name plus **(core)**, **(addon)**, **(custom)** (`lib/sidecars/custom`), or **(repo)** (git). Type pills are **webui**, **api**, **openapi**, **cli**, and **gui**, one pill per type. A `gui` card shows Open Name linking to `/desktop` and has no Pin. A CLI card shows which source Bros is using. `/terminal` is the desktop sidecar terminal plus a name list of npm, nix, apt, and run apps. Add and edit open the same dialog. Install and remove progress shows in the terminal. Drag the bar under the terminal to change its height. The Desktop card links to that page. `/desktop` fills the content column beside the dock. One iframe shows the stream. A short strip has an app drawer of every gui sidecar and package GUI. A drawer click opens a sidecar window only when that sidecar is already running, and runs a package command inside the desktop. It does not start a sidecar container. Stop in the drawer kills that window and leaves the sidecar and the desktop up. A `gui` interface has no host-port Open. The list uses a wide (horizontal) card when the current filter has a single item. Two or more cards stay one wide card per row until that list is at least 48rem, then compact in two columns. A narrow list stacks even when the viewport is wide. Start, Stop, Restart, Open, Logs, Terminal, Edit, and Update sit on the left of that row and stay visible when the card is collapsed. Every card has Logs. A web UI Open reads Open Name (:port). A gui Open reads Open Name (Open Cursor) and sits with those Open links, to the right of Restart and before Logs. The chevron stays on the right edge of the same row. Autostart and Pin in nav sit on the next line. The chevron opens URLs and the rest. Cards do not show a host-port line. Card padding is 15px so the description is about 10px wider than a default padded card. There is no `/models` page.
- Chat/Providers: Providers is Ollama (sidecar then host when Settings enable host Ollama is on), Popular services (12 always-listed OpenAI-compat cards), then Custom providers. Ollama titles are **Ollama (core)** and **Ollama (host port:N)**. Rows show host:port (`127.0.0.1:11435` sidecar publish, not Docker DNS) or the API host for popular/custom, with copy. Custom keeps open-in-new-tab on that endpoint; Ollama sidecar and host rows do not. Popular rows use a globe Open control to the console/keys site (`siteUrl` on the preset), not the API host. Both Ollama cards load collapsed; selecting a card expands pull + installed models on that card; the chevron (or a second click on the open card) collapses the panel for the rest of the session. Ollama, Popular, and Custom lists stay full page width whether a card is open or collapsed. Each row has a compact **Chat** label above the switch. Ollama and Popular cards expand in-place: models first, then settings (sidecar GPU, host port, or popular key/name/models). The Ollama pull combobox is about three-quarters of the content width; its menu matches the input width. Installed Ollama rows keep name/size, then a compact Chat switch and a small red ban icon (no Delete text). Ban opens an Are you sure? dialog that names the model; confirm calls the existing delete API. In-progress and queued pulls appear at the top of that list immediately (progress on the row, no switch, Stop / Resume + ban). Pull itself does not show a spinner. There is no separate progress card above the list. Popular catalog rows (and custom lists that share that UI) use the same compact Chat switch and no ban — Bros does not own those remote ids. No settings cog on those rows. Custom still uses a settings cog that opens a dialog. GPU only in the sidecar dropdown, after the installed-model list. Ollama Chat defaults on; popular/custom Chat defaults off until a key passes a live health probe. Health uses a subtle badge: Ready, Need an API key, Invalid key, or Unreachable — not running/stopped. Popular settings are key + models (no Delete). Host card appears only when Settings enable host Ollama is on (listed even if the daemon is down). Host panel has Scan plus an optional port override. Unconfigured popular cards stay listed. Chat is provider dropdown then model dropdown (order: sidecar, host if enabled, popular, custom; Chat-off providers omitted; Chat-off models omitted). Heading is Popular services, never “Paid providers”.
- Chat turns: user is a right-aligned bubble (cool accent wash, not a stacked gray card) with copy + edit under it. Edit + resend stops an in-flight reply and truncates from that user turn. Assistant is left. Both bodies use the same prose styles as Docs. Label `ASSISTANT · <modelId>` is a small muted line under the assistant body, from the stored request model, not the current dropdown. No model text when the row has none. Whole-reply copy is raw markdown (check after copy). Fenced code uses a snippet header with a copy control (check after copy).
