# DESIGN — Bros

## Visual

- Dark surface with cool blue/teal accents (`--bros-accent`, `--bros-accent-2`)
- Thin themed scrollbars (≈6px, muted thumb, no arrows) via theme `main.css` for page content. Dock Previous chats and Docs tree scroll with hidden bars + recents chevron hints; Dashboard…Status never scroll
- Shared shell via theme `layouts/default.vue` (`BrosAppNav` / `BrosNavBar` / `BrosPageShell`); same chrome in app and website; only nav links differ
- Docs markdown uses theme `.bros-prose` + `ProsePre` (identical on website and in the app). Chat assistant and user bodies use the same stack (`MDC` + `.bros-prose` + `ProsePre`) so headings, lists, code, tables, and blockquotes match Docs inside the thread/bubbles.
- Docs site landing vs app dashboard: same theme, different homepage (`src/website` owns `/`; app `/` is the dashboard)
- Docs site local: `pnpm docs:dev` → http://127.0.0.1:3056/bros/ (`baseURL` `/bros/`)

## Navigation

- **Desktop (lg+):** left dock column in the app frame. Main content sits beside it (flex); the panel occupies layout width so content shrinks/grows. Resizable by dragging the right edge. Persist `open` / `width` / `iconMode` in localStorage. Drag below 80px snaps to icon-only (icons + hover titles); drag past 112px snaps labels back. Icon-only active/hover highlight is a compact box around the glyph, not a full-rail bar that covers the icon. One brand (dock when open; top bar brand + panel toggle only when dock closed).
- **Mobile:** hamburger overlay drawer. No dock column; overlay is OK.
- App order: Dashboard, New chat, Agent, Providers, Sidecars, Status (fixed height, no scroll), divider, Previous chats (open list, collapsible; divider + heading stay fixed; list scrolls with hidden scrollbar; up chevron under the heading and down chevron under the list when more recents sit off-screen), divider, Previous agents (same pattern for `kind=agent` threads), divider, pinned sidecar UIs, divider, Docs (collapsible directory tree of every `/docs` page, own hidden scrollbar) + Settings, footer GitHub: https://github.com/jasenmichael/bros
- `/chat` is a new empty conversation: full-height column, centered greeting + rounded composer. Provider then model sit left in a compact tools row above the composer, context size on the right — not a fat header card or empty message well. The provider trigger stays as wide as the longest option (`Ollama (host port:11434)`), not the selected label — picking Groq or Gemini does not shrink it. The menu matches that width so full Ollama labels stay visible. The model trigger stays compact; the open menu is wider so full Ollama names (`freehuntx/qwen3-coder:14b`) are not truncated. Ellipsis on either picker only when the viewport is too narrow. The Message composer stays the full tools-row width, not the provider trigger width. `/chat/:id` (and the first send on `/chat`) fills the column with turns; composer docks to the bottom; only the message thread scrolls (not the app frame). Opening a saved thread pins that scroller to the latest turn after render. Recents live in the dock, not a Chat left rail. Each recent has a ⋮ menu: Rename, Delete. While waiting: centered muted **thinking… 1.2s** plus compact **Stop**. Send stays the arrow, disabled until the stream ends. Composer stays editable. After tokens start, **Stop** sits on the live assistant meta line. A round **Voice to text** mic sits left of Send/Stop (same pill radius); recording pulses the accent and does not auto-send. Assistant meta sits under the body: role+model left, `1.4s · 128 tok` right when stored, plus a copy icon for the stored raw markdown.
- Docs site: Home, then the same collapsible docs tree (Start, App, Sidecars, Contribute, API)
- Docs pages: breadcrumbs above the title, walked from that tree
- Sidecar web UIs with `navPinned` appear below a divider (no Pinned heading). LAN pins are `http://127.0.0.1:<publish>/`, or `http://127.0.0.1:<publish>/${id}/` when `proxy.public` and the UI listens under that path. Via-tunnel pins for `proxy.public` webuis are same-host `/${id}/`. No shipped pack opts in today (OpenCode LAN is `http://127.0.0.1:4097/`). Pin in nav is only on cards with a published `webui`. Published APIs keep Open, not Pin.

## Pages

- `/` — website: marketing landing. App: dashboard widgets (Bros, Docker, disk, GPU, Ollama sidecar+host providers, Tunnel). **Bros services** lists every Bros-managed Docker container (app + each `bros-sc-*` service). Sidecar rows sit in a later **Sidecar snippets** section (publish port only). No Sidecars summary card in the widget grid. No full Status table on Home
- `/status` — detail: Bros app, Docker, disk, GPU, host Tunnel, **Bros services** (same container inventory as Home), each sidecar port/state/error, autostart/pin, logs links. No Start/Stop/Restart on Core Ollama or Whisper. Whisper enable lives on Settings. Recovery uses a Nuxt UI toast (`useToast` / `UApp`), not a custom snackbar.
- `/docs`, `/docs/*` — identical docs-layer pages in website and app (theme layout + prose)
- `/agent`, `/agent/:id` — same column as Chat, including the voice mic and last provider/model memory. Empty greeting is **What should we look up?** with no thread list. Recents stay in Previous agents. While tools run, the waiting line is **Searching …** or **Reading host**, then the answer. Sources sit under the assistant body. User turns use the same Copy / Edit / Resend controls as Chat.
- `/chat`, `/chat/:id`, `/providers`, `/sidecars`, `/sidecars/:id/logs`, `/settings` — app-only. Settings is compact BrosPageShell: Chat (two full-width textareas + Save), Whisper switch (off by default; on pulls images then starts the sidecar), Host Ollama switch (off by default), then read-only paths, then full-width passkey inputs. Sidecars page sections: **Core** (Ollama and Whisper — no Start/Stop/Restart/Autostart), then **Addon sidecars** (shipped OpenCode / Open WebUI / Firecrawl / Firecrawl UI plus sidecars/custom and git packs; Add sidecar + From a repo). Each card has a refresh icon next to running/stopped. Each card’s source badge is **bros** (shipped), **repo** (git), or **custom** (`sidecars/custom`). Each section is one column and uses a wide (horizontal) card when it has a single item. Two or more cards stay compact/stacked in `lg:grid-cols-2` — Core has Ollama and Whisper, so that section is two-up on large screens. Two or more cards stay compact/stacked in `lg:grid-cols-2`. Mobile is always one wide card per row. `/models` 301s to `/providers`.
- Chat/Providers: Providers is Ollama (sidecar then host when Settings enable host Ollama is on), Popular services (12 always-listed OpenAI-compat cards), then Custom providers. Ollama titles are **Ollama (core)** and **Ollama (host port:N)**. Rows show host:port (`127.0.0.1:11435` sidecar publish, not Docker DNS) or the API host for popular/custom, with copy. Custom keeps open-in-new-tab on that endpoint; Ollama sidecar and host rows do not. Popular rows use a globe Open control to the console/keys site (`siteUrl` on the preset), not the API host. Both Ollama cards load collapsed; selecting a card expands pull + installed models on that card; the chevron (or a second click on the open card) collapses the panel for the rest of the session. Ollama, Popular, and Custom lists stay full BrosPageShell width whether a card is open or collapsed. Each row has a compact **Chat** label above the switch. Ollama and Popular cards expand in-place: models first, then settings (sidecar GPU, host port, or popular key/name/models). The Ollama pull combobox is about three-quarters of the content width (`w-3/4 max-w-3xl`); its menu matches the input width. Installed Ollama rows keep name/size, then a compact Chat-style `USwitch` and a small red ghost `i-lucide-ban` icon (no Delete text). Ban opens a UModal Are you sure? that names the model; confirm calls the existing delete API. In-progress and queued pulls appear at the top of that list immediately (progress on the row, no switch, Stop / Resume + ban). Pull itself does not show a spinner. There is no separate progress card above the list. Popular catalog rows (and custom lists that share that UI) use the same compact Chat `USwitch` and no ban — Bros does not own those remote ids. No settings cog on those rows. Custom still uses a settings cog (UModal). GPU only in the sidecar dropdown, after the installed-model list. Ollama Chat defaults on; popular/custom Chat defaults off until a key passes a live health probe. Health uses a subtle `UBadge`: Ready, Need an API key, Invalid key, or Unreachable — not running/stopped. Popular settings are key + models (no Delete). Host card appears only when Settings enable host Ollama is on (listed even if the daemon is down). Host panel has Scan plus an optional port override. Unconfigured popular cards stay listed. Chat is provider dropdown then model dropdown (order: sidecar, host if enabled, popular, custom; Chat-off providers omitted; Chat-off models omitted). Heading is Popular services, never “Paid providers”.
- Chat turns: user is a right-aligned bubble (cool accent wash, not a stacked gray card) with copy + edit under it. Edit + resend stops an in-flight reply and truncates from that user turn. Assistant is left. Both bodies render through theme `.bros-prose` + `ProsePre` (same as Docs), not a second Tailwind `prose` stack. Label `ASSISTANT · <modelId>` is a small muted line under the assistant body, from the stored request model, not the current dropdown. No model text when the row has none. Whole-reply copy is raw markdown (check after copy). Fenced code uses a snippet header with a copy control (check after copy).
