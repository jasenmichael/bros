# SPEC — Bros

**Bros** (**B**oxed **R**untime **O**rchestration **S**ystem) manages Docker containers for local AI applications and development. It runs a desktop in the browser.

This file states product behavior and stable contracts: pages, HTTP routes, status codes, ports, YAML and env keys, `sidecar.yml`, Docker rules, and user-visible outcomes. It does not name the language, frameworks, or source paths. Those live in [STACK.md](STACK.md).

## Parts

Three parts:

- **Host command** `bros`. The default action is start. Do not call this command the CLI. A **cli interface** is a command on a sidecar, with no URL.
- **Browser app.** Chat, Providers, Sidecars, Status, Settings, `/desktop`, and `/terminal`. `/desktop` is one Wayland session in the browser.
- **Docs.** Repo `docs/` is served at `/docs` in the app and on the site. The app does not override those pages.

### Host command

`bros` with no command, or `bros start`, starts Bros and the sidecars. Prod builds the image. Dev (`BROS_DEV=1` or `--dev`) does not. The start waits until `/api/health` answers, then prints `http://<host>:<port>` and, when a tunnel URL is set, that URL on the next line. After compose is up, sidecar Ollama starts if needed and the internal `bros` model is stamped. A stamp miss warns and does not fail the start.

`bros stop` stops every `bros-sc-*` sidecar and `bros-desktop`, then the core container. It prints `Bros exited.` and exits 0. `bros restart` stops, then starts. `bros status` prints compose state and the health check. `bros check` looks for git, image, and model updates, and prompts before updating when stdin is a TTY. `bros update` (alias `upgrade`) pulls git, the submodule, and images, rebuilds the app and desktop images, and stamps the model when Ollama is already up. It does not start the stack.

`bros service install` installs a Linux systemd user unit whose start command is `bros -D`. `bros service uninstall` disables and removes that unit. `bros service status` prints the unit status.

`bros run <command>` and `bros shell` run in `bros-desktop` when that container is already up. They do not start the stack. The workdir is `/home/bros/workspace`. `bros shell` is bash.

Flags: `--dev` (same as `BROS_DEV=1`), `-D` / `--daemon` (background prod start; ignored when dev is on), `-i` / `--interactive` (foreground; default; one Ctrl+C stops the stack, prints `Bros exited.`, and exits 0; a second Ctrl+C exits 130), `-c` / `--config PATH` (host `bros.yml`), `--verbose`, `-h` / `--help`, `-v` / `--version`.

Env: `BROS_DIR` (directory of the `bros` script, symlink-resolved), `BROS_HOME` (alias), `BROS_PORT` (default `3055`), `BROS_HOST` (default `0.0.0.0`), `BROS_DEV=1`. The published command page is [docs/cli.md](docs/cli.md). That page states the same commands, flags, and env. This file wins when they differ.

## Surfaces

Chat, Providers, Sidecars, Status, Settings, Docs. UI at `BROS_HOST`:`BROS_PORT` (default `0.0.0.0:3055`, so the app is on the local network). `0.0.0.0` prints as `http://127.0.0.1:3055` and each host LAN address on that port. There is no Agent page.

## Chat

`/chat` is the conversation page (a provider and a model, centered greeting and composer — no left rail, no empty message well). A send without both returns 400. A stored model id `gateway` does the same until the thread gets a real model. The composer has a **Voice to text** mic that records in the browser and transcribes through the Whisper core sidecar. Settings **Enable Whisper** is off by default; while off, transcribe returns an error and does not start or pull images. While on, a stopped sidecar may be started. Toggle recording; transcribed text appends to the message and does not auto-send. The provider list omits any provider whose Chat switch on Providers is off. The model dropdown omits models whose per-model Chat switch is off. New chats and provider switches restore the last provider and that provider’s last model from this browser; a saved thread still opens on its stored `modelId`. `/chat/:id` opens a saved thread: messages fill the column and the composer docks at the bottom. Opening a saved thread pins the scroller to the latest turn after render (every `:id` navigation). User turns are visually distinct (right-aligned). The dock label is **New chat**. Previous chats sit under Status as an open, collapsible list and open `/chat/:id`. The bottom group is pinned sidecar UIs, then Docs + Settings, then the GitHub footer. Chat is one streamed completion. It does not run a tool loop.

A conversation is created on the first send, not when opening `/chat`. After the first successful assistant reply, sidecar model **bros** writes a short title from the first user prompt (`Label:`). Later messages do not retitle. If generate fails, keep `New chat` or the first line of the prompt. The model is internal (not listed in Chat or Providers). Recents overflow is Rename and Delete only. Each assistant message stores the `modelId` used for that request; the UI shows `ASSISTANT · <modelId>` under the assistant body. Older rows without a stored model omit the extra text. The assistant meta line keeps duration and token counts on the right when the provider sent them (reload uses the stored row, not the live dropdown). A copy control next to that meta copies the stored raw markdown of the whole reply (fences included). Fenced snippets still have a copy control. User turns show copy and edit under the bubble. Edit + resend stops an in-flight stream (same abort as **Stop**), deletes that user turn and every later row (`POST /api/chat/:id/truncate`), then sends the edited text with the same Chat settings prepend/description as a normal send. Title still auto-titles only the first successful reply of a New chat. While a reply is in flight, Send stays the arrow and is disabled until the stream ends. The composer stays editable. Centered **thinking…** shows elapsed time and **Stop** until the first assistant token. After tokens start, **Stop** sits on the live assistant meta line. **Stop** aborts the stream. Provider then model sit on the left of the tools row; the selected model's context size sits on the right when Ollama reports it. Assistant and user bodies render as markdown with the same visualization as Docs. Fenced code snippets include a copy control. Settings Chat fields are the `rules` and `personality` skill bodies (`$BROS_HOME/data/config/skills/<id>/SKILL.md`), not YAML, env, or the browser. Each user turn loads those bodies as one system message. Empty bodies are omitted. Stored turns stay as typed. Internal `bros` `Label:` title generate never receives them.

## Agent

There is no `/agent` page and no custom tool loop. Chat is one completion. A later cut can drive tools through OpenCode or OpenHands. Bros does not embed the OpenHands SDK.

## Docs

Shared markdown lives in repo `docs/`. Routes `/docs` and `/docs/*` are the same pages in the app and on the static site. The app does not override them. Layout, CSS, and markdown visualization (nav chrome + prose) are shared; only nav links differ.

Docs index, dock, and website nav share one tree (Start, App, Sidecars, Contribute, API). The tree lists every `docs/` page, including Providers → Ollama + Custom providers and all twelve Popular service pages. App dock **Docs** expands that tree (collapsible; hidden scrollbar). Dashboard…Status stay un-scrolled. Previous chats and Docs each scroll. Website nav is Home plus the same tree. Docs pages show breadcrumbs above the title (Docs / App / Providers / Custom providers).

The website owns marketing `/` and publishes to GitHub Pages (`baseURL` `/bros/`). Website nav: Home plus the docs directory tree. Landing cards: Chat, Providers, Sidecars, Development. The Bros app owns dashboard `/` plus Chat, Providers, Sidecars, Status, and Settings.

## Bootstrap

One file, `$BROS_HOME/data/config/bros.yml`: `public_url`, `enable_host_ollama` (default off), `enable_whisper` (default off), `workspace` (host directory, default `data/home/workspace`). `BROS_PUBLIC_URL` overrides `public_url`. `BROS_HOST_WORKSPACE` overrides `workspace`. Chat prepend and assistant description are the `rules` and `personality` skills. Settings reads and writes those files. They never apply to internal `bros` titles. Settings **Repair data dir** confirms, then runs `chown` on the host data directory as `BROS_HOST_UID`:`BROS_HOST_GID`. Start and stop do not.

**`BROS_DIR` (host):** when running `bros` with `BROS_DIR` unset, the real directory of the `bros` script (symlink-aware: `~/.local/bin/bros` → `$BROS_DIR/bros`). Installed clone is typically `~/.bros`. `BROS_HOME` is an alias (`BROS_HOME` alone still sets `BROS_DIR`). Override with `BROS_DIR` or `BROS_HOME`. Data defaults to `$BROS_DIR/data` (`BROS_DATA_DIR` override, host bind `BROS_HOST_DATA_DIR`):

- `$BROS_HOST_DATA_DIR` → app `/app/data` (SQLite, logs, tunnel, `passkey`, `proxy-key`, `session-secret`). Container stdout and stderr are followed into `data/var/logs/<service>.log`.
- `$BROS_HOST_DATA_DIR/home` → Desktop `$HOME` (`/home/bros`). Desktop mounts this whole directory. A sidecar mounts only the `home` paths its `sidecar.yml` lists, at the same path under its own `$HOME`. Two packs that list the same path fail discovery. The Bros user is `BROS_HOST_UID`:`BROS_HOST_GID` for Desktop and every sidecar.
- `$BROS_HOST_DATA_DIR/home/workspace` → `$HOME/workspace`. `bros.yml` `workspace` or `BROS_HOST_WORKSPACE` replaces the host path. A sidecar gets it only when that sidecar lists `workspace`.
- `$BROS_HOST_DATA_DIR/home/.local/sidecar-bins` → Desktop `$HOME/.local/sidecar-bins`, first on Desktop `PATH`. Sidecar CLI wrappers live here. App binaries do not.
- `$BROS_HOST_DATA_DIR/home/.ollama` and `home/.config/ollama` → Ollama `$HOME`. Downloaded models stay under `.ollama/models`. `$BROS_HOST_DATA_DIR/sidecars/ollama/bros-model` stays `/bros-model` (read-only packaged tree).
- `$BROS_HOST_DATA_DIR/home/.config/Cursor` and `home/.cursor` → Cursor app home. `$BROS_HOST_DATA_DIR/home/.config/cursor` and `home/.local/share/cursor-agent` → Agent app home. Desktop mounts all of `home`, so these are the directories those apps create.
- `$BROS_HOST_DATA_DIR/home/.config/opencode`, `home/.local/share/opencode`, `home/.local/state/opencode` → OpenCode `$HOME`.
- `$BROS_HOST_DATA_DIR/home/.pi` → Pi `$HOME/.pi`.
- `$BROS_HOST_DATA_DIR/home/.cache/huggingface` → OpenJEV. Whisper mounts `home/.cache/huggingface/hub` only.
- `$BROS_HOST_DATA_DIR/home/.cache/vllm` and `home/.cache/flashinfer` → OpenJEV.
- `$BROS_HOST_DATA_DIR/sidecars/openwebui/data` → Open WebUI `/app/backend/data`.
- `$BROS_HOST_DATA_DIR/sidecars/firecrawl/postgres`, `redis`, `rabbitmq` stay service data, not home paths.
- `$BROS_HOST_DATA_DIR/config/apps` → Desktop `/opt/bros/apps`. Not a home directory.

The image sets `BROS_DIR=/app`, so in-container data is `/app/data`. Start does not copy leftover named volumes into those dirs.

All other settings live in SQLite (`bros.sqlite`) and the UI.

## Sidecars

Managed Compose projects **outside** the Bros app stack. Three kinds:

- **Core** — `lib/sidecars/core/`. **Ollama** (`lib/sidecars/core/ollama`) always runs. No disable env. No Start/Stop/Restart/Autostart UI. **Whisper** (`lib/sidecars/core/whisper`) is core and stopped until Settings **Enable Whisper** (SQLite `meta.enable_whisper`, default off). Turning it on runs `docker compose pull`, then starts the sidecar. Turning it off stops it. Later boots autostart Whisper only while that flag is on (`compose up`, no separate pull). No Start/Stop/Restart/Autostart on Sidecars / Status / Home. `POST /api/sidecars/whisper/start`, `…/stop`, and `…/restart` return 400.
- **Addon** — shipped packs under `lib/sidecars/addon/` (OpenCode, Open WebUI, Firecrawl, Firecrawl UI, OpenJEV, Pi). Optional. A fresh install does not enable or start them. Autostart is SQLite (`autostart`, default off). Turn Autostart on and restart Bros, and that sidecar starts with Bros. Press Start still starts one that is off. Env-disabled packs do not start. `/desktop` opens and closes a window on a running sidecar and does not start or stop the container. The same default applies to custom packs. Mark a pack disabled with `BROS_SIDECAR_OPENCODE=0` / `BROS_SIDECAR_OPENWEBUI=0` / `BROS_SIDECAR_FIRECRAWL=0` / `BROS_SIDECAR_FIRECRAWL_UI=0` / `BROS_SIDECAR_OPENJEV=0` / `BROS_SIDECAR_PI=0` or `BROS_SIDECARS_DISABLE=opencode,openwebui,firecrawl,firecrawl-ui,openjev,pi`. Disabled packs stay listed and are not autostarted. Env disable does not apply to core.
- **Custom** — user-created under `lib/sidecars/custom/<id>/` or cloned into `lib/sidecars/custom/<name>/` (that tree’s `sidecars/` dir). Only `lib/sidecars/custom/README.md` is tracked. Pack files stay on disk. A custom pack can later move to `lib/sidecars/addon/` or `lib/sidecars/core/`. An addon can later move to core.

Discover merges `lib/sidecars/core`, `lib/sidecars/addon`, and `lib/sidecars/custom` (a direct package, or `<repo>/sidecars/*`). Production mounts those at `/app/sidecars/core`, `/app/sidecars/addon` (read-only), and `/app/sidecars/custom` (writable). Dev does not mount `/app/sidecars/{core,addon,custom}`; discovery uses `/app/lib/sidecars`. Shipped ids win; custom cannot reuse `ollama`, `whisper`, addon slugs, app routes, or Popular slugs. Compose project name `bros-sc-<id>` on shared external Docker network `bros` (CLI or dockerode create it if missing; core compose does not own it). The Sidecars page is one list. Above the cards: Add sidecar and From a repo, then one line of three segmented controls — All / Running / Stopped, interface type (webui, api, openapi, cli, gui), and Core / Addon / Custom. Each matches All / Running / Stopped and stays content-width. Each card heading is the name plus **(core)**, **(addon)**, **(custom)** (`lib/sidecars/custom`), or **(repo)** (git clone). Type pills show each interface type once: **webui**, **api**, **openapi**, **cli**, **gui**. A refresh icon on each card re-fetches `/api/sidecars` (running/stopped and the rest of that payload). Add sidecar writes `lib/sidecars/custom/<id>/`; From a repo clones into `lib/sidecars/custom/<name>/`. A package may include a `data/` tree that mirrors container paths; Bros copies missing files into `data/<id>/` before `compose up` and does not overwrite existing volume files. A section with one card uses the wide (horizontal) layout. Two or more stay one wide card per row until the section container is at least 48rem, then compact in two columns. A narrow section stacks even when the viewport is wide. Saving an additional sidecar prompts a restart confirm. Git rows have Update (`git pull`) and prompt restart when compose changed.

A `cli` card shows the command (`bin`, else `command`) and no URL. A `gui` block lists each `gui` interface command (`command`, else `bin`) and does not repeat `cli` bins. CLI-only packs stay running (`sleep infinity`) so the network can exec them. Pi joins network `bros` when started. They do not autostart on a fresh install. Each `cli` bin is probed at `/host-home/.local/bin/<bin>` (a bridge script does not count). The host shell keeps a real install. While that sidecar is running, the Desktop PATH wrapper in `data/home/.local/sidecar-bins` is `docker compose exec` into it. When it is stopped and the host bin exists, that wrapper execs the host bin. Bros does not write host PATH wrappers. Shell names (`bash`, `sh`, `dash`, `zsh`, `fish`, `rbash`) are never wrapped. App `bin` and `clis` stay inside Desktop. Sidecar CLIs stay on the Desktop PATH. A bridge script already in `~/.local/bin` is deleted on the next sync. `expose_host` stays stored and unused.

**Desktop** (`lib/sidecars/core/desktop`) is a core sidecar that always starts. No host port. Image and container `bros-desktop`. Compose service `desktop`. Selkies captures one Wayland display. `labwc` nests on it and provides window management and XWayland. `/desktop` is one iframe of that stream at `/desktop/view/`, proxied to `http://desktop:3000`. Selkies mode is websockets. Basic auth is off. The session cookie authorizes the page and the stream. The proxy key does not. The browser never receives a Docker address.

Core, addon, and custom apps share one install. Core apps (npm, pnpm, bun) are always enabled. Their settings and cache are home directories declared on the app (`home/.npm`, `home/.local`, `home/.local/share/pnpm`, `home/.bun`). Addon apps include Cursor and Agent, both off until enabled. Cursor is `kind: deb` with the Linux x64 latest URL (`https://api2.cursor.sh/updates/download/golden/linux-x64-deb/cursor/latest`). Its home is `.config/Cursor` and `.cursor`. `cursor` is the CLI and the GUI command. Agent is `kind: run` with `curl https://cursor.com/install -fsS | bash`. Its home is `.local/share/cursor-agent` and `.config/cursor`. Commands are `agent` and `cursor-agent`. An addon app ships in `lib/apps/addon/<id>/config.yml`, listed and off until enabled. A custom app is `data/config/apps/<id>/config.yml`. Scripts sit beside that file. Enable flags stay in `data/`. The Desktop image build installs enabled package apps into `/usr/local`. Each enabled package install is its own image layer. Deb files and curl trees stay in the Docker build cache `bros-pkg`, not under `data/`. `/settings/apps` shows a version beside the label when Desktop reports one. Package updates can run together. `kind: run` has no check. Its Update writes a force stamp and rebuilds Desktop so that curl runs again. Core always. Addon and custom only when enabled. Container start does not install. Bros writes that set to `$BROS_HOST_REPO/lib/sidecars/core/desktop/enabled-apps` when `BROS_HOST_REPO` is set, otherwise under the app directory, which is the Desktop image build context. Enabling or disabling a package app rebuilds the image. An unchanged start does not. A `services` entry on an enabled package app is a command or `script` relative to the app directory. It runs inside Desktop only after Start on Apps. `kind: run` may set `uninstall` to a command or a script beside the config. Enable installs the app and does not start the service. Stop keeps it stopped across a Desktop restart. A sidecar process starts in that sidecar image. Its `cli`, `gui`, and `webui` interfaces are what Desktop gets. A package `webui` publish is a host port on Desktop, written with app `volumes` into `config/apps-compose.yml`. Open is `http://127.0.0.1:<publish>/`. Fixed binds stay in the Desktop compose file. `/settings/apps` and `bros app update <id>` check and update an app. A package app updates through its package manager. A sidecar app updates by pulling its image and recreating. Core stays enabled. Nix is a nixpkgs name. Apt stays in the image layer. Kind `deb` is an https URL. Install downloads that file and `apt-get install`s it. When a path segment is `latest`, check follows redirects and compares that resolved URL to the one saved at install. A URL without that tag does not report an update. Core apt packages are `lib/sidecars/core/desktop/core-apt.yml`.

`/terminal` embeds ttyd from `http://desktop:7681` at `/terminal/session`. That shell is user `bros`, with its own uid so the prompt user stays `bros` while the desktop user `abc` keeps `PUID`. The container hostname is `bros`. The shell starts in `$HOME/workspace`. The prompt shows `~/workspace` there. The terminal account `bros` is a separate uid. It is not the Bros host uid. `bros run` and `bros shell` exec in `bros-desktop` when it is already up. Desktop `PATH` starts with `$HOME/.local/sidecar-bins`. On desktop start, a name in `$HOME/.local/bin` is removed when that command is already in the image for an enabled app. A Herdr session whose saved directory is missing is set aside so the server can listen. A `cli` or `gui` interface is available there without a compose entry per sidecar. Flags: [docs/cli.md](docs/cli.md).

Any sidecar can mix `webui`, `api`, `openai`, `cli`, and `gui`. Interface type `cli` is a command. Those show on `/terminal` under **Expose CLIs** when the pack is not env-disabled, except shells. Package `cli` rows show under Apps only when that app is enabled. Bash stays the Terminal shell and is not exposed. Interface type `gui` is a window command. Sidecar `gui` interfaces show in the Apps drawer on `/desktop` when the pack is not env-disabled. Package `gui` interfaces show there only when that app is enabled. A click opens the sidecar window when that sidecar is already running and does not start it. Package apps exec inside `bros-desktop`. The Apps drawer lists Terminal first. That row opens `foot` in `/home/bros/workspace`, and the desktop session starts the same foot. Cursor's window passes `--no-sandbox` with `HOME=/home/bros`. Sidecar apps stay `docker exec` with `DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-0`, and `XDG_RUNTIME_DIR=/tmp/bros-run`. Stopping an app kills that process. The sidecar stays up. The desktop stays up. Named volume `bros-x11` is `/tmp/.X11-unix`. Named volume `bros-run` is `/tmp/bros-run`. A `gui` interface stores `command` only. No `publish`. No host port. No per-app iframe. `/gui` is gone. Slugs `gui` and `terminal` are reserved.

Package apps already run inside `bros-desktop`, so they share `127.0.0.1`. A sidecar that draws on the desktop uses that container's network namespace. It does not publish a host port. A pack that publishes a port cannot also take that namespace. No shipped sidecar takes that namespace. Start fails with a clear error when `bros-desktop` is not running. Service sidecars with no `gui` interface keep their own network. From the desktop namespace they stay reachable by Docker DNS (`ollama:11434` and the same pattern). An app that listens on `127.0.0.1` in the desktop is reachable from other desktop apps, and the reverse.

Every `webui` interface must set `publish` in `sidecar.yml` and map `publish:containerPort` in `docker-compose.yml`. Open is only a published `webui`. A published `api` or `openai` lists copyable host and Docker-network URLs with `basePath` (`openai` defaults to `/v1`) and has no Open button. OpenJEV ships a `webui` for FastAPI `/docs` plus `api`/`openai`. Pin in nav is only for a published `webui`. Optional `proxy.public: true` on a `webui` enables a Bros path proxy at `/${id}/` only when that UI natively listens under the prefix. That prefix is allowlisted by discovered sidecar id — `/opencode` does not match `/opencode-extra`, and `/chat` stays Bros. Via-tunnel Open/Pin use same-host `/${id}/` (passkey like `/chat`). LAN Open/Pin stay `http://127.0.0.1:<publish>/` (or with interface `basePath` when set), or `http://127.0.0.1:<publish>/${id}/` when the UI listens under that path. No shipped pack opts in today. OpenCode 2 (`ghcr.io/anomalyco/opencode:2.0.32`) serves `/` and the Sidecars card shows its password. OpenCode stays LAN-only. Every `api` and `openai` interface is proxied on the Bros hostname at `/<id><basePath>` with `/<id>` stripped before the upstream request. `/ollama/api` and `/ollama/v1` reach `http://ollama:11434`. Whisper, Firecrawl, Open WebUI, and OpenJEV API ports use the same rule. Those paths accept a Bros session or `Authorization: Bearer` the proxy key. Web UI proxies still need `proxy.public` and keep the prefix. OpenCode stays LAN-only. Host Ollama has no tunnel path. Sidecars copy lists host publish and Docker DNS URLs with `basePath` for `api` and `openai` (no bare origin beside the path). Compose-app Bros → sidecar APIs always use that Docker DNS on network `bros` (Ollama `http://ollama:11434`, Whisper `http://whisper:8000`), including when the browser is on `public_url`. When the app runs on the host, it uses `http://127.0.0.1:<publish>` (`BROS_OLLAMA_PORT` / `BROS_WHISPER_PORT` overrides). Other containers still use internal DNS. Host **publish** ports **3000** and **8080** are forbidden. Env overrides (`BROS_OLLAMA_PORT`, `BROS_OPENCODE_PORT`, `BROS_OPENWEBUI_PORT`, `BROS_FIRECRAWL_PORT`, `BROS_FIRECRAWL_UI_PORT`, `BROS_WHISPER_PORT`, `BROS_OPENJEV_PORT`) are escape hatches for host publish and for the app process on the host.

Bros always `compose up` each sidecar on its **publish** port. Start fails if that port is already taken. Occupancy of the upstream default (Ollama 11434) does **not** skip the Bros sidecar (publish **11435**).

**Host Ollama** (Chat/Providers) is a second built-in provider (`ollama-host`). Settings **Enable host Ollama** (`bros.yml` `enable_host_ollama`) is **off by default**. Off omits the row from `GET /api/providers`, the Chat picker, and the Providers page; `/api/providers/ollama-host/*` returns 404. The provider row stays so Chat-enable and `config.disabledModels` survive. Bros never starts the host daemon. When on, live scan finds one daemon: a saved probe port is exclusive (no silent fallback); else probe default **11434** first (`host.docker.internal` / `BROS_HOST_GATEWAY` from the app container, `127.0.0.1` when the app runs on the host). Skip if that port is sidecar publish **11435** or `bros-sc-ollama`. Then published host ports on running Docker Ollama containers (image `ollama/ollama` or name containing `ollama`; skip project/name `bros-sc-ollama` and publish **11435**). Then leftover `/proc/net/tcp`+`tcp6` LISTEN ports (when the app runs on the host) and other published ports. In the app container, host `/proc` is invisible — still probe host-gateway **11434**, not only the container listen table. Verify with `GET /api/version` JSON `{ version }`. Skip sidecar publish **11435** and any port whose `publishedPortOwner` project is the Bros Ollama sidecar. First `GET /api/version` hit wins. Do not HTTP-probe 1–65535 on every list. `POST /api/providers/ollama-host/scan` busts the 30s cache. Sidecar Ollama stays `ollama` at DNS `http://ollama:11434` (host publish **11435**). The Compose app never uses the sidecar publish port for Chat/Providers/STT (from inside the container `127.0.0.1` is the Bros process). When the app process is on the host, Chat/Providers use `http://127.0.0.1:11435` for the sidecar (`BROS_OLLAMA_PORT` if set) and `http://127.0.0.1:<probe>` for host Ollama — not Docker DNS (`ollama`, `host.docker.internal`). Chat picks a provider, then a model, in order: sidecar, host (if enabled), Popular services (fixed catalog), then custom — omitting any provider whose Chat switch is off, and omitting models stored in that provider’s `config.disabledModels`. If the current Chat model belongs to a provider the user then disables, Chat falls back to the next enabled provider. `modelId` is `providerId/model` (`ollama/llama3.2`, `ollama-host/llama3.2`, `openai/gpt-4o-mini`, `my-proxy/qwen2.5`). GPU / pull into `$BROS_HOME/data/home/.ollama` is the sidecar; host pull/chat use the host Ollama disk (no Bros disk-fit check). Popular services and custom providers are OpenAI-compatible (base URL + optional key + model names), not a paid catalog. Keys live in SQLite only (no `OPENAI_API_KEY` env bootstrap).

Dev compose is `BROS_DEV=1` or `./bros --dev` (`docker-compose.dev.yml`). Prod is the default. `bros start` (and a dev start) remove legacy `forgebox-sc-*` containers before up. `bros stop` and interactive Ctrl+C stop all `bros-sc-*` sidecars, then the core stack — so sidecars never stay orphaned beside a stopped app. A finished stop prints `Bros exited.` and exits 0. A second Ctrl+C exits 130. First start also brings up sidecar Ollama and installs the internal `bros` model when the packaged GGUF is present (see Internal specialist).

Keep product language **sidecar** / **Sidecars** (routes `/sidecars`, APIs `/api/sidecars`, file `sidecar.yml`).

## Status

`/status` reports Bros app, Docker, disk, GPU, host Tunnel, and each sidecar’s port/state/error plus autostart/pin. `/api/status` also includes `enableHostOllama`, `containers` (every Bros-managed Docker container: app `bros` plus each `bros-sc-*` service, including stopped), and a `phase` on each sidecar: `starting`, `running`, `stopped`, or `error`. Sidecar autostart is not awaited by the first page request. While a pack is in that startup set and not yet running, `phase` is `starting`. An autostart that throws stays `phase: error` for the process lifetime. `/api/status` includes `booting`, true only until this process finishes that autostart pass. The boot overlay covers the page only while `booting` is true. The first HTML uses that flag, and the open page polls `GET /api/health` for it, so a slow `/api/status` cannot hold the cover. A refresh after the pass does not paint the cover. Login, setup, package install, and a later sidecar start do not hold it. The dashboard paints before `/api/dashboard/summary` returns (`server: false`) and shows that loading state. Home does not render the full Status table. Sidecar Ollama recovery also sets `ollamaRestartNotice` on the status payload (toast, not a Status table row).

Home (`/`) is a fixed hub, not a widget catalog. `GET /api/dashboard/summary` returns recent chats (latest eight: title, `modelId`, `updatedAt`), providers on for Chat, sidecar phase, an attention list, and the host tunnel. The summary does not live-probe provider keys. Provider rows are Ollama (core), host Ollama when Settings enable it, and any other provider with Chat on. Ollama counts as ready for chat only while its sidecar phase is `running` and Chat is on. Other Chat-on rows count without a health probe. Active Ollama pulls (`queued` or `running`) are listed on that panel. Sidecar rows are discovered packs that are not disabled. A host Open link (`http://127.0.0.1:<publish>/`) is included only for a `webui` when the request is not via-tunnel; the page shows Open when that sidecar is `running`. Attention appears only for a Docker socket failure, a sidecar in `error`, Ollama `stopped`, data disk under 2 GiB or under 10% free, or zero providers ready for chat while Ollama is `running`. GPU, the container inventory, API paths, CLI commands, and host memory stay off Home. `/status` still has **Bros services** for the grouped container inventory. Live hub bodies come from `GET /api/dashboard/summary`, not from rendering `/api/status`. There is no saved widget order.

Dashboard also has a **Tunnel** card for a **host** `cloudflared` process. It is not a sidecar. A non-empty `public_url` (`BROS_PUBLIC_URL`, else `BROS_TUNNEL_HOST` from `.env`, else YAML) is the enable + hostname signal: `bros` / helper startup starts a **named** tunnel (`cloudflared tunnel create`, `cloudflared tunnel route dns <id> <hostname>` which creates a CNAME to `<id>.cfargotunnel.com`, then `cloudflared tunnel --config $BROS_HOME/data/var/tunnel/config.yml run bros`). `config.yml` has hostname ingress, catch-all `http_status:404`, `protocol: http2`, and `edge-ip-version: 4`. Override with `BROS_TUNNEL_PROTOCOL` (`http2` / `quic` / `auto`) and `BROS_TUNNEL_EDGE_IP_VERSION` (`4` / `6` / `auto`). Quick `*.trycloudflare.com` is only used when `public_url` is unset and the card is turned on. If start fails, `status.json` `error` is shown on the Dashboard card and Status. `route dns` “already exists” is success. If `route dns` times out on Cloudflare’s API, the named tunnel still starts and Dashboard shows the CLI warning plus the expected CNAME (not a leftover REST `PUT /zones/.../tunnels/.../routes` as the only message). If the logged-in Cloudflare account does not own the hostname’s DNS zone (`tunnel route dns` CNAME mismatch or zone error), the tunnel does not start and that reason is shown. Runtime connection errors after the last successful register (for example QUIC idle timeout) are shown even while the process is up. Turning the card off stops the process until the next `./bros` / helper start.

A request is **via-tunnel** when any of `cf-ray`, `cf-connecting-ip`, or `cf-visitor` is present, `cdn-loop` contains `cloudflare`, or the request Host matches `public_url`, optional `BROS_TUNNEL_HOST`, or the last advertised hostname. `/api/status` includes `viaTunnel`, `tunnelHost`, and `tunnel`. While via-tunnel, stop is refused (API 403) and the Dashboard toggle is disabled so the session cannot lock itself out. Start remains allowed. Chat, Providers, and Whisper STT keep working: the browser talks only to Bros `/api/*` on that hostname; Bros talks to sidecars on Docker network `bros`. The same hostname also proxies `api` and `openai` interfaces (`/ollama/v1` and the other base paths). Sidecar Open/Pin stay host-local except `proxy.public` webuis, which share the Bros hostname and passkey (see Sidecars). No shipped pack sets `proxy.public` today.

Dev through the tunnel must still load the client.

## Auth

Shared passcode. Source of truth is plaintext file `{dataDir}/passkey` (in Docker: `/data/passkey`). On startup Bros creates the file if missing and prints the key to logs. Settings / setup update the file. A separate `{dataDir}/proxy-key` (mode 0600, printed once, rotated in Settings) authorizes `api` and `openai` proxy paths only. `Authorization: Bearer <proxy-key>` does not log into the app. Bros `/api/*`, pages, and webui proxies stay on the session cookie. Session cookie `bros_session` (HttpOnly, SameSite=Lax, Path=/; host-only; Secure on HTTPS including the Cloudflare tunnel, not on local HTTP). `/status` is gated like other app pages. Via-tunnel stop-lock does not apply to login.

## Sidecar kinds

**Core:** `ollama` (Bros publish **11435**, container 11434; host install stays **11434**). Sidecars / Status / Home have no Start, Stop, or Restart for it. Autostart cannot be turned off. `POST /api/sidecars/ollama/start`, `…/stop`, and `…/restart` return 400. Desktop always starts and has no host port. Whisper is core and is not must-run (Settings **Enable Whisper**, default off). Host Ollama (`ollama-host`) is not a sidecar and is not locked. A server health check restarts the sidecar internally when the compose process is down, or after two failed `GET /api/version` probes (5s each). It skips that check during autostart and while Ollama is starting, and does not restart for a single slow pull or a single slow probe. `/api/status` and `/api/sidecars` expose `ollamaRestartNotice` `{ recoveredAt, lastRestartReason }` once per recovery. A recovery shows one toast.

**Addon:** `opencode` (publish **4097**), `openwebui` (publish **3080** → container 8080), `firecrawl` (publish **3002**, scrape API; Playwright 3000 stays internal), `firecrawl-ui` (publish **3081** → container 8080), `openjev` (publish **8092** → container 8080, System One API + FastAPI `/docs`; NVIDIA GPU; default `OPENJEV_GPU_UTIL=0.80`, encoders on CPU for ~16 GB), `pi` (CLI, no host port), `whisper` (publish **8090** → container 8000, Chat STT; not a Chat provider). Start/Stop/Restart, autostart, and logs stay in the UI. Cursor and Agent are addon apps on Desktop.

**Custom:** user and git sidecars. Same controls as addons. Cloudflare tunnel is a host `cloudflared` process, not a sidecar.

## Providers

Providers (`/providers`) lists **Ollama** (sidecar, then host when Settings enable host Ollama is on), **Popular services** (12 always-listed OpenAI-compat cloud cards), then **Custom providers**. Sidecar and popular cards always appear; host appears only when that Settings toggle is on. Display titles are **Ollama (core)** and **Ollama (host port:N)** (live probe/override; stored SQLite names stay `Ollama (core)` / `Ollama (host)` without a port). Row health is **Ready**, **Need an API key**, **Invalid key**, or **Unreachable** — never running/stopped (those words are sidecar process state on Status). Ready means a live probe succeeded (Ollama version/tags, or keyed `GET /models` with the saved key). A non-empty key field alone is not Ready. Rows show host:port (`127.0.0.1:11435` for sidecar publish, host probe/override for host, API host for popular/custom) — not the provider id — with copy. Custom still opens that endpoint in a new tab. Ollama sidecar and host rows keep copy only (no external-link). Popular rows open the provider console/keys page (`siteUrl` on the preset), not the API host. Both Ollama cards start collapsed (no pull or installed-model list until the user opens one). Selecting a different Ollama card expands pull and the installed-model list on that card (the other collapses). The chevron or a second click on the already-open card collapses the panel; the card stays selected for the session. Each provider row has a **Chat** switch (label above the switch) that only removes that provider from the Chat picker — it does not stop the sidecar, host Ollama, or any other provider. Ollama sidecar and host default Chat **on**; Popular services and custom providers default Chat **off**. Keyed Chat can turn on only after Bros saves a key and the health probe succeeds; Chat-on with no key is invalid and is turned off on load. User can still turn Chat off without deleting the key. Internal specialist `bros` still uses sidecar Ollama when that provider is off for Chat. Ollama and Popular cards expand in-place: installed or listed models first, then settings under that list (sidecar GPU, host port override, popular API key + optional model list). Each installed Ollama model row has a Chat switch (default on; off stores the name in that provider’s `config.disabledModels` and hides it from that provider’s Chat picker) and a compact red ban icon. Delete needs an Are you sure? confirm that names the model; cancel does nothing. Popular catalog rows (and custom lists that share that UI) have the same Chat switch and the same `config.disabledModels` store; they have no delete — Bros does not own the remote catalog. The models textarea is a seed/fallback, not an allowlist. No settings cog on Ollama or Popular. GPU never appears for host/popular/custom. Popular settings have no Delete and no pull. Custom providers still use a settings cog that opens a dialog. Custom providers are OpenAI-compatible (base URL, optional key, model names); Add custom lives under that heading. Popular slugs are reserved (cannot delete, cannot reuse as a custom id). Heading is never “Paid providers”.

Recommended pulls are official (and verified community) Ollama tags whose on-disk size is **≤ 16 GB**. `qwen3-coder:14b` is not a library tag (official coder is `:30b` / `:480b`); use `freehuntx/qwen3-coder:14b` or `qwen2.5-coder:14b`. 30B tags (~19 GB) stay in the Ollama list, not Recommended.

Any valid Ollama name can be typed and pulled (`name:tag` or community `owner/name:tag`). The catalog dropdown opens only while the pull input is empty; a typed or selected valid name closes it and enables Pull (click the input again to reopen and pick something else). Selecting a catalog row stores the model `value`, not the display label (`name · size`). `POST /api/providers/:id/models/pull` `{ model }` (`:id` is `ollama` or `ollama-host`) returns `{ ok, job }` immediately — Pull does not spin. Progress is `GET /api/providers/:id/models/pull` and `activePulls` on `GET /api/providers`. Jobs persist in SQLite `ollama_pull_jobs` (`$BROS_HOME/data/bros.sqlite`) so a Bros/container restart still shows incomplete rows and auto-resumes interrupted `running` jobs. One pull runs at a time per provider (`ollama` vs `ollama-host`); further Pulls are `queued` and wait. That row is inserted at the top with percent/status/bytes and has no Chat switch until the model is installed; Stop aborts the Ollama fetch (or drops a queued job), Resume calls pull again, and the ban icon confirms then stops, drops the job, and tries `DELETE /api/delete` (Ollama may keep incomplete blobs). Sidecar compose sets `OLLAMA_NOPRUNE=1`. Host Ollama needs the operator to set the same on the daemon — Bros cannot. User-added names persist in that Ollama provider's `config.customModels` list (SQLite via `upsertProvider`) and appear under **Yours** in the Providers pull menu. Registry errors (including TLS handshake timeout) are shown as returned; one retry on timeout/5xx, never fake success.

OpenAI-compat Chat (`kind: openai`, popular and custom) sends `stream_options: { include_usage: true }`, reads `delta.content` or `delta.reasoning_content`, and adds OpenRouter `HTTP-Referer` + `X-Title: Bros`. Native Anthropic stream stays for leftover `kind: anthropic` rows; popular Anthropic is seeded as `kind: openai`. Remote `GET /models` runs only when a key is saved.

## Internal specialist

Packaged GGUF + Modelfile live in git submodule `vendor/bros-model` ([jasenmichael/bros-model](https://github.com/jasenmichael/bros-model)). When the Ollama sidecar is up (on sidecar start and on `/api/providers`), Bros copies `models/`, `ollama/`, and `scripts/` onto `$BROS_HOST_DATA_DIR/sidecars/ollama/bros-model`, bind-mounts that tree at `/bros-model:ro`, and runs `bash /bros-model/scripts/install-ollama.sh` inside `bros-sc-ollama` (`ollama create bros`). Skip if tags already have `bros` and the GGUF size/mtime stamp matches. Missing GGUF: log once, skip; chat still works.

Ollama name `bros` is reserved for the app. First skill is `Label:` chat titles (see Chat) — not the conversation chat model, not listed in Chat or Providers, pull/delete returns 400. Titles always use the trained `bros` model and the short tag. Typical model update: bump the pinned submodule, then release a new Bros version.

## Gateway

There is no gateway picker and no `/api/gateway`. Chat send is the selected provider and model. Public `/v1` is later (M12-02).

## Tools

Chat is one completion. No tool schemas, no provider Tools switch, and no MCP calls on a send. The `Label:` title call does not get tools. Task skill files stay on disk and are not loaded on a send.

## MCP

Bros stores HTTP MCP servers in SQLite `meta` key `mcp_servers` and toggles them in Settings. Chat does not call them. A later tool engine can.

## Skills

User skills are `$BROS_HOME/data/config/skills/<id>/SKILL.md`, seeded once from `lib/skills/` when missing. `personality` and `rules` load on Chat turns. The rules skill says the model has no tools and must not pretend to browse, read files, or run commands. `data/config/assistant.md` only names those skills. Job skills stay out of the prompt until a later tool engine loads them. The catalog also reads `.cursor/skills`, `.claude/skills`, `.agents/skills`, and `.opencode/skills` under the host home and the working directory when those directories exist. Those copies are read-only. Internal `label`, `task`, and `tasks` live in `$BROS_HOME/data/skills-internal`, seeded from `lib/skills/internal/`, and are not in the catalog. A send does not load `tasks/<mode>.md`. `Label:` titles use the short tag on the trained `bros` model.

## ACP

ACP is not implemented. No route, SDK, or UI. OpenCode or OpenHands as a tool engine is later. Bros does not embed the OpenHands SDK.
