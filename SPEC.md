# SPEC — Bros

**Bros** (**B**oxed **R**untime **O**rchestration **S**ystem) manages Docker containers for local AI applications and development. It runs a desktop in the browser.

This file states product behavior and stable contracts: pages, HTTP routes, status codes, ports, YAML and env keys, `config.yml`, Docker rules, and user-visible outcomes. It does not name the language, frameworks, or source paths. Those live in [STACK.md](STACK.md).

## Parts

Three parts:

- **CLI** `bros`. The default action is start. A **cli interface** is a command on a docker app, with no URL.
- **Browser app.** Chat, Providers, Apps, Status, Settings, `/desktop`, and `/terminal`. `/desktop` is one Wayland session in the browser.
- **Docs.** Repo `docs/` is served at `/docs` in the app and on the site. The app does not override those pages.

### Host command

Product version is `0.0.1`. `bros -v` prints it. The first published release is that number and uses the Ollama app's packaged model release `1.0.0`. After those tags exist, the commit type on a pull request chooses the next number (`feat` minor, `fix` and `perf` patch, a breaking change major). The merge publishes when that tag is missing. A later packaged-model release whose version changed releases Bros as a minor bump that records the new model release.

`bros` with no command, or `bros start`, starts Bros and the docker apps. Prod builds the image. Dev (`BROS_DEV=1` or `--dev`) does not. The start waits until `/api/health` answers, then prints `http://<host>:<port>` and, when a tunnel URL is set, that URL on the next line. After compose is up, docker app Ollama starts if needed and the internal `bros` model is stamped. A stamp miss warns and does not fail the start.

`bros stop` stops every `bros-*` docker app and `bros`, then the core container. It prints `Bros exited.` and exits 0. `bros restart` stops, then starts. `bros status` prints compose state and the health check. `bros check` calls `POST /api/apps/check` after `/api/health`. `bros update` (alias `upgrade`) on a release downloads `bros-<os>-<arch>.tar.gz` for this machine (`BROS_RELEASE_URL` overrides that URL) and keeps `data/`. On a source checkout, when the branch is `main` or `master`, it runs `git pull --ff-only` (and fails if that pull fails); on any other branch, it prints a loud skip and continues without syncing remote. Then it updates the submodule, rebuilds the CLI, and calls `POST /api/apps/rebuild`. The local `bros` image is built, not pulled from a registry. A base already present at its pinned digest is reused. A missing base is pulled once. It replaces a running `bros` container. It does not start it when it is stopped. It does not pull or replace other docker apps.

`bros service install` installs a Linux systemd user unit whose start command is `bros -D`. `bros service uninstall` disables and removes that unit. `bros service status` prints the unit status.

`bros run <command>` and `bros shell` run in `bros` when that container is already up. They do not start the stack. The workdir is `/home/bros/workspace`. `bros shell` is bash.

Flags: `--dev` (same as `BROS_DEV=1`), `--use-runner` (same as `BROS_USE_RUNNER=1`; prod uses the UI runner even when host `pnpm` is on `PATH`; with dev it exits `dev does not use the UI runner`), `-D` / `--daemon` (background prod start; ignored when dev is on), `-i` / `--interactive` (foreground; default; one Ctrl+C stops the stack, prints `Bros exited.`, and exits 0; a second Ctrl+C exits 130), `-c` / `--config PATH` (host `bros.yml`), `--verbose`, `-h` / `--help`, `-v` / `--version`.

Env: `BROS_DIR` (directory of the `bros` script, symlink-resolved), `BROS_DIR` (alias), `BROS_PORT` (default `3055`), `BROS_HOST` (default `0.0.0.0`), `BROS_DEV=1`, `BROS_USE_RUNNER=1`. The published command page is [docs/cli.md](docs/cli.md). That page states the same commands, flags, and env. This file wins when they differ.

## Surfaces

Chat, Agents, Providers, Apps, Status, Settings, Docs. UI at `BROS_HOST`:`BROS_PORT` (default `0.0.0.0:3055`, so the app is on the local network). `0.0.0.0` prints as `http://127.0.0.1:3055` and each host LAN address on that port. There is no `/agent` page.

## Chat

`/chat` is the conversation page (a provider and a model, centered greeting and composer — no left rail, no empty message well). A send without both returns 400. A stored model id `gateway` does the same until the thread gets a real model. The composer has a **Voice to text** mic that records in the browser and transcribes through the Whisper docker app. Settings **Enable Whisper** is off by default; while off, transcribe returns an error and does not start or pull images. While on, a stopped docker app may be started. Toggle recording; transcribed text appends to the message and does not auto-send. The provider list omits any provider whose Chat switch on Providers is off. The model dropdown omits models whose per-model Chat switch is off. New chats and provider switches restore the last provider and that provider’s last model from this browser; a saved thread still opens on its stored `modelId`. `/chat/:id` opens a saved thread: messages fill the column and the composer docks at the bottom. Opening a saved thread pins the scroller to the latest turn after render (every `:id` navigation). User turns are visually distinct (right-aligned). The dock label is **New chat**. Previous chats sit under Status as an open, collapsible list and open `/chat/:id`. The bottom group is pinned docker app UIs while that docker app is running and not disabled (a stored pin stays; the dock ignores it while the docker app is disabled or stopped), then Docs + Settings, then the GitHub footer. Chat is one streamed completion. It does not run a tool loop.

A conversation is created on the first send, not when opening `/chat`. After the first successful assistant reply, docker app model **bros** writes a short title from the first user prompt (`Label:`). Later messages do not retitle. If generate fails, keep `New chat` or the first line of the prompt. The model is internal (not listed in Chat or Providers). Recents overflow is Rename and Delete only. Each assistant message stores the `modelId` used for that request; the UI shows `ASSISTANT · <modelId>` under the assistant body. Older rows without a stored model omit the extra text. The assistant meta line keeps duration and token counts on the right when the provider sent them (reload uses the stored row, not the live dropdown). A copy control next to that meta copies the stored raw markdown of the whole reply (fences included). Fenced snippets still have a copy control. User turns show copy and edit under the bubble. Edit + resend stops an in-flight stream (same abort as **Stop**), deletes that user turn and every later row (`POST /api/chat/:id/truncate`), then sends the edited text with the same Chat settings prepend/description as a normal send. Title still auto-titles only the first successful reply of a New chat. While a reply is in flight, Send stays the arrow and is disabled until the stream ends. The composer stays editable. Centered **thinking…** shows elapsed time and **Stop** until the first assistant token. After tokens start, **Stop** sits on the live assistant meta line. **Stop** aborts the stream. Provider then model sit on the left of the tools row; the selected model's context size sits on the right when Ollama reports it. Assistant and user bodies render as markdown with the same visualization as Docs. Fenced code snippets include a copy control. Settings Chat fields are the `rules` and `personality` skill bodies (`$BROS_DIR/data/config/skills/<id>/SKILL.md`), not YAML, env, or the browser. Each user turn loads those bodies as one system message. Empty bodies are omitted. Stored turns stay as typed. Internal `bros` `Label:` title generate never receives them.

## Agents

`/agents` is the job board: Issues, Needs you, Queue, Failed, Completed. It polls about every 2 seconds. There is no `/agent` page and no redirect. Chat stays one completion and does not run a tool loop. There is no `/jobs/:id` page and no `/projects` page.

A project is one git directory directly under Workspace. The directory name is the repo name. **Add project** on `/agents`, under the board, registers `owner/name`, the default branch, and a path under Workspace. Runtime settings sit under that and start closed. Empty path uses `/home/bros/workspace/<repo>`. If that directory is missing, Bros clones `owner/name` into it once. It does not make a second clone or a worktree, and it does not `git init`. The board scans enabled projects only. Each project stores **Issue branch to**, `staging` (default) or `main`. The issue branch `{kind}/{slug}` is the pull request head. `staging` opens that pull request into `staging` and keeps one standing pull request `staging` into `main`. `main` opens the job pull request into `main` and does not open a standing `staging` pull request. Bros never merges. **Delete branch after merge** (default on) deletes the job branch after a human merges it into that base. It does not delete `main` or `staging`.

**Auto preflight** (default on) enqueues PreFlight about every 30 seconds. **start preflight** still works when that is off. PreFlight uses the Bros Ollama docker app and the selected preflight model and writes a Task Spec. Auto preflight accepts that spec. Otherwise the job waits until **Approve implement**. **Auto-approve implement** (default off) accepts a manual preflight. The selected runtime then runs in the background inside Desktop. The cwd is `/home/bros/workspace/<repo>`. The job checks out the issue branch in that directory. No second clone and no git worktree. The agent does not commit, push, or open the pull request. Bros commits, pushes, and stops at `awaiting_pr`. The commit subject is `{kind}: {title}` (`bug` is `fix`, `feature` is `feat`). That subject is what the version scanner reads. **Approve PR** (or **Auto-approve PR**, default off) opens the pull request.

The runtime is Cursor or Claude, one choice for every project, default Cursor. Cursor runs `cursor-agent acp` from `~/.local/bin/cursor-agent` in the Desktop home. When that file is missing, Bros installs it with `curl -fsS https://cursor.com/install | bash` as the desktop user before the first job. That does not enable the Agent app. Claude runs the Claude addon binary. One open job per project and issue. The branch starts from that repo's default branch. The commit author is the GitHub user for the token. If that lookup fails, the job fails. Timeout is 45 minutes. Implement retries twice. A completed job whose pull request is closed without merge puts the issue back on the board. A merged pull request stays completed. **Clear** on a failed or timed out job deletes the row, not the repo.

The GitHub token is one encrypted value. The field shows whether it is set and the last 4 characters. Paste replaces it. Clear removes it. On every start, `GH_TOKEN`, else `GITHUB_TOKEN`, else `GITHUB_PAT`, replaces the stored token when that variable is set. An unset variable does not clear a token pasted in the UI. The same token is a mode `0600` git credential for `https://github.com` under the Desktop home, and the desktop user's credential helper is that store. Bros does not install `gh` and does not run `gh auth login`. The token is not exported into the desktop session or the Compose environment. Settings on `/agents` are the runtime, an optional Cursor API key, the GitHub token, the preflight model (models already on the Bros Ollama docker app), and the four switches above. A `kind: run` runtime installs on a Desktop rebuild. The page says so and links to `/settings/desktop/apps`.

A later cut can drive Chat tools through OpenCode or OpenHands. Bros does not embed the OpenHands SDK.

## Docs

Shared markdown lives in repo `docs/`. Routes `/docs` and `/docs/*` are the same pages in the app and on the static site. The app does not override them. Layout, CSS, and markdown visualization (nav chrome + prose) are shared; only nav links differ.

Docs index, dock, and website nav share one tree (Start, App, Docker apps, Apps, Contribute, API). The tree lists every `docs/` page, including Providers → Ollama + Custom providers and all fourteen Popular service pages. App dock **Docs** expands that tree (collapsible; hidden scrollbar). Dashboard…Status stay un-scrolled. Previous chats and Docs each scroll. Website nav is Home plus the same tree. Docs pages show breadcrumbs above the title (Docs / App / Providers / Custom providers).

The website owns marketing `/` and publishes to GitHub Pages (`baseURL` `/bros/`). Website nav: Home plus the docs directory tree. Landing CTAs: Get started, Install, Development. Landing cards: Chat, Providers, Apps, Desktop, Agents, Development. The Bros app owns dashboard `/` plus Chat, Providers, Apps, Status, and Settings. Product pitch mirrors the repo README; install and development detail stay in `docs/install` and `docs/development`.

## Bootstrap

One file, `$BROS_DIR/bros.yml`: `tunnel` (default off), `public_url`, `enable_host_ollama` (default off), `enable_whisper` (default off), `workspace` (host directory, default `data/home/workspace`). Host tunnel enable is opt-in: `BROS_TUNNEL` when set, else YAML `tunnel` (`true` / `1` / `yes`). Hostname is separate: `BROS_PUBLIC_URL`, else `BROS_TUNNEL_HOST`, else YAML `public_url`. Hostname alone does not enable the tunnel. `BROS_WORKSPACE` overrides `workspace`. A leftover `$BROS_DIR/data/config/bros.yml` is moved to `$BROS_DIR/bros.yml` when the home file is missing. Chat prepend and assistant description are the `rules` and `personality` skills. Settings reads and writes those files. They never apply to internal `bros` titles. Settings **Repair data dir** confirms, then runs `chown` on the host data directory as `BROS_HOST_UID`:`BROS_HOST_GID`. Start and stop do not.

**`BROS_DIR` (host):** when running `bros` with `BROS_DIR` unset, the real directory of the `bros` script (symlink-aware: `~/.local/bin/bros` → `$BROS_DIR/bros`). Installed clone is typically `~/.bros`. `BROS_DIR` is an alias (`BROS_DIR` alone still sets `BROS_DIR`). Override with `BROS_DIR` or `BROS_DIR`. Data defaults to `$BROS_DIR/data` (`BROS_DATA_DIR` override, host bind `BROS_DATA_DIR`):

- `$BROS_DATA_DIR` → app `/app/data` (SQLite, logs, tunnel, `passkey`, `proxy-key`, `session-secret`). Container stdout and stderr are followed into `data/var/logs/<service>.log`.
- `$BROS_DATA_DIR/home` → Desktop `$HOME` (`/home/bros`). Desktop mounts this whole directory. A docker app mounts only the `home` paths its `config.yml` lists, at the same path under its own `$HOME`. Two packs that list the same path fail discovery. The Bros user is `BROS_HOST_UID`:`BROS_HOST_GID` for Desktop and every docker app.
- `$BROS_DATA_DIR/home/workspace` → `$HOME/workspace`. `bros.yml` `workspace` or `BROS_WORKSPACE` replaces the host path. A docker app gets it only when that docker app lists `workspace`.
- `$BROS_DATA_DIR/home/.local/app-bins` → Desktop `$HOME/.local/app-bins`, first on Desktop `PATH`. App `launch.sh` wrappers live here. Installed binaries do not.
- `$BROS_DATA_DIR/home/.ollama` and `home/.config/ollama` → Ollama `$HOME`. Downloaded models stay under `.ollama/models`. `$BROS_DATA_DIR/apps/ollama/bros-model` stays `/bros-model` (read-only packaged tree).
- `$BROS_DATA_DIR/home/.config/Cursor` and `home/.cursor` → Cursor app home. `$BROS_DATA_DIR/home/.config/cursor` and `home/.local/share/cursor-agent` → Agent app home. Desktop mounts all of `home`, so these are the directories those apps create.
- `$BROS_DATA_DIR/home/.config/opencode`, `home/.local/share/opencode`, `home/.local/state/opencode` → OpenCode `$HOME`.
- `$BROS_DATA_DIR/home/.pi` → Pi `$HOME/.pi`.
- `$BROS_DATA_DIR/home/.cache/huggingface` → OpenJEV. Whisper mounts `home/.cache/huggingface/hub` only.
- `$BROS_DATA_DIR/home/.cache/vllm` and `home/.cache/flashinfer` → OpenJEV.
- `$BROS_DATA_DIR/apps/openwebui/data` → Open WebUI `/app/backend/data`.
- `$BROS_DATA_DIR/apps/firecrawl/postgres`, `redis`, `rabbitmq` stay service data, not home paths.
- `$BROS_DATA_DIR/apps/omniroute/data` and `apps/omniroute/redis` → OmniRoute. `apps/omniroute/.env` holds `OMNIROUTE_JWT_SECRET` (not a pack-dir `.env`).
- `$BROS_DATA_DIR/config/apps` → Desktop `/opt/bros/apps`. Not a home directory.

The image sets `BROS_DIR=/app`, so in-container data is `/app/data`. Start does not copy leftover named volumes into those dirs.

All other settings live in SQLite (`bros.sqlite`) and the UI.

## Apps

Ollama and Whisper are **core docker apps** under `lib/apps/core/<id>/` (`config.yml` with `kind: docker` plus `docker-compose.yml`). Desktop is not a docker app. The store page is `/settings/desktop/apps`. Store list is `GET /api/apps` (docker including core, plus package apps). Compose control is `/api/apps/*`. Addon boot list is `BROS_APPS_ENABLED`.

- **Ollama** (`lib/apps/core/ollama`) always runs (enabled by default; Settings disable comes later). No Start/Stop/Restart/Autostart on Apps. `POST /api/apps/ollama/start`, `…/stop`, and `…/restart` return 400.
- **Whisper** (`lib/apps/core/whisper`) stays stopped until Settings **Enable Whisper** (SQLite / bros.yml `enable_whisper`, default off). Turning it on runs `docker compose pull`, then starts the app. Turning it off stops it. Later boots start Whisper only while that flag is on. No Start/Stop/Restart/Autostart on Apps. `POST /api/apps/whisper/start`, `…/stop`, and `…/restart` return 400.

Docker apps are kind `docker`. Shipped addons are `lib/apps/addon/<id>/` (Open WebUI, Firecrawl, Firecrawl UI, OpenJEV, Pi, OmniRoute). Each directory holds `config.yml` and `docker-compose.yml`. Volume and home binds live only in that compose file (`$BROS_DATA_DIR/apps/<id>/…` or `home/…`). A `home` field on `config.yml` is ignored. A fresh install does not start them. Core docker apps boot when enabled (Ollama always; Whisper when Settings Enable Whisper is on). Other docker apps honor SQLite Autostart on boot (default off), and also boot when listed in `BROS_APPS_ENABLED` (comma addon ids). Press Start to run one without Autostart. Ollama and Whisper ignore `BROS_APPS_ENABLED`. `/desktop` opens and closes a window on a running docker app and does not start or stop the container.

A custom docker app is `data/config/apps/<id>/` with the same files. It is not in the repo. A git clone lands in that tree (`<name>/` or `<name>/apps/*`). Moving that directory to `lib/apps/addon/<id>/` or `lib/apps/core/<id>/` makes it a shipped app. The id and the kind stay. Enable flags stay outside the directory in `data/config/enabled-apps`.

Discover reads core docker apps in `lib/apps/core/<id>`, addon docker apps in `lib/apps/addon/<id>`, and custom apps in `data/config/apps`. Package apps share `lib/apps/core|addon` with non-docker `config.yml` kinds. Shipped ids win. Custom cannot reuse `ollama`, `whisper`, an addon id or slug, app routes, or Popular slugs. A disabled addon still reserves its id and slug. Compose project name `bros-<id>` on shared external Docker network `bros` (the CLI or dockerode create it if missing; the Bros compose file does not own it). The Apps page (`/settings/desktop/apps`) is one list in sections by kind (docker, then each package-manager kind). Every app uses one card and shows only the actions for that kind and its interface types. Above the cards: Add, Add package, From a repo, and Scan, then one line of four segmented controls — All / Running / Stopped, interface type (webui, api, openapi, cli, gui), Core / Addon / Custom, and package manager (docker, npm, pnpm, bun, deno, uv, cargo, nix, apt, deb, run). Each matches All / Running / Stopped and stays content-width. Scan lists top-level npm, pnpm, bun, uv, cargo, and nix packages inside container bros, under the filters. A name that matches a package app of that kind is plain text. Adopt writes an enabled custom package config and does not install. Running means the docker container is running, or a package service is running. Each card heading is the name plus **(core)**, **(addon)**, **(custom)** (`data/config/apps`), or **(repo)** (git clone). Type pills show each interface type once: **webui**, **api**, **openapi**, **cli**, **gui**. A refresh icon on each card re-fetches `/api/apps` (running/stopped and the rest of that payload). Add writes `data/config/apps/<id>/config.yml` with `kind: docker`. From a repo clones into `data/config/apps/<name>/`. Core docker apps may include a `data/` tree; Bros copies missing files into `data/<id>/` before `compose up` and does not overwrite existing volume files. Docker apps rely on compose binds only. A section with one card uses the wide (horizontal) layout. Two or more stay one wide card per row until the section container is at least 48rem, then compact in two columns. A narrow section stacks even when the viewport is wide. Saving an additional pack prompts a restart confirm. Git rows have Update (`git pull`) and prompt restart when compose changed.

A `cli` card shows the command (`bin`, else `command`) and no URL. A `gui` block lists each `gui` interface command (`command`, else `bin`) and does not repeat `cli` bins. CLI-only packs stay running (`sleep infinity`) so the network can exec them. Pi joins network `bros` when started. They do not autostart on a fresh install. Each `cli` bin is probed at `/host-home/.local/bin/<bin>` (a bridge script does not count). The host shell keeps a real install. While that docker app is running, the Desktop PATH wrapper in `data/home/.local/app-bins` is `docker compose exec` into it. When it is stopped and the host bin exists, that wrapper execs the host bin. Bros does not write host PATH wrappers. Shell names (`bash`, `sh`, `dash`, `zsh`, `fish`, `rbash`) are never wrapped. App `bin` and `clis` stay inside Desktop. Docker app CLIs stay on the Desktop PATH. A bridge script already in `~/.local/bin` is deleted on the next sync. `expose_host` stays stored and unused.

**Desktop** is the Wayland session inside container `bros`. The HTTP server is the UI host, outside that container. Image, container, and Compose service for the desktop are `bros`. Selkies captures one Wayland display. `labwc` nests on it and provides window management and XWayland. Selkies listens on container port 3000 and is published at `127.0.0.1` on `BROS_STREAM_PORT` (3300). ttyd listens on container port 7681 and is published at `127.0.0.1` on `BROS_TTYD_PORT` (7681). The UI host listens on `BROS_PORT` (3055). `/desktop` is one iframe of that stream at `/desktop/view/`. The proxy target is `BROS_DESKTOP_STREAM_ORIGIN` (a host UI uses the localhost publish; container `bros-ui` uses `http://bros:3000`). Selkies mode is websockets. Sharing is off (`SELKIES_ENABLE_SHARING=false`) so one `/desktop` client owns the display and resizes it to the iframe; a second tab takes over instead of letterboxing. Basic auth is off. The session cookie authorizes the page and the stream. The proxy key does not. The browser never receives a Docker address. The stream page follows the Bros page visibility, so the picture plays while `/desktop` is showing and pauses when that page is hidden.

Core, addon, and custom apps share one install. Core apps (node, cargo, pnpm, bun, deno, uv) are always enabled. node is the core app. Its Nix package is `nodejs` and its commands are `node`, `npm`, and `npx`. npm is a package-manager kind. Their settings and cache stay under the Desktop home mount. Addon apps include Cursor, Agent, Claude, Paperclip, jq, and OpenCode, all off until enabled. Cursor is `kind: deb` with the Linux x64 latest URL (`https://api2.cursor.sh/updates/download/golden/linux-x64-deb/cursor/latest`). `cursor` is the CLI and the GUI command. Agent is `kind: run` with `curl https://cursor.com/install -fsS | bash`. Commands are `agent` and `cursor-agent`. Claude is `kind: run` with `curl -fsSL https://claude.ai/install.sh | bash`. Command is `claude`. Paperclip is `kind: npm` with spec `paperclipai`. Command is `paperclipai`. It publishes web UI **3100**. Ensure installs it with npm into `/home/bros/.local`. Start runs `paperclipai run` in `/home/bros`. Open is `http://127.0.0.1:3100/` on `/apps` only while enabled, Forward to host is on, and the service is running. Stop, run onboard in the Terminal, then Start, then Open. The first visit claims the instance. An offline page titled Paperclip is offline is Paperclip’s own service-worker fallback (down, unclaimed, missing host publish, or Paperclip auth/origin mismatch for http://127.0.0.1:3100/) — not a Bros wrapper. Host publish ports land in config/apps-compose.yml under Compose service bros. jq is `kind: apt` with spec `jq`. It has no `cli` or `gui`. OpenCode is `kind: npm` with spec `@opencode/cli`. Command is `opencode`. It publishes web UI host **4096** to container port **4096**. Start runs `opencode serve --hostname 0.0.0.0 --port 4096` in `/home/bros`. The server password is in the service log (`data/var/logs/apps/opencode.log`). Ensure installs `@opencode/cli` into `/home/bros/.local` after `node`, `npm`, and `npx` exist. Open is `http://127.0.0.1:4096/` on `/apps` only while enabled, Forward to host is on, and the service is running. An addon app ships in `lib/apps/addon/<id>/config.yml`, listed and off until its id is in `data/config/enabled-apps`. A missing file means none enabled. `data/config/apps` is custom apps only. Enable flags are not copies of shipped configs. Shipped configs stay in `lib/apps`. A custom app is `data/config/apps/<id>/config.yml`. A custom package app is enabled when that file is written. Scripts sit beside that file. Enable flags stay outside the directory in `data/config/enabled-apps`. Only `kind: run` is a Desktop image layer. Other enabled package apps install after the Desktop session answers, one at a time. A later start skips a command that already runs. Deb files and curl trees stay in the Docker build cache `bros-pkg`, not under `data/`. `/apps` shows the installed version beside the label and on a GUI card. Optional `version` in `config.yml` is that command. Otherwise the command is `<bin> --version`, then `<bin> -V`. Present is `command -v`. Check stays on every settings row except `kind: run`. Update shows only after Check finds a newer version. For node that version is the `BROS_NODE_VERSION` pin, and Check never offers a Node newer than the pin. One shared bottom-right toast shows ensure on every page, one card at a time. If Devbox and Nix are already present, the card says `Devbox and Nix found` and shows their versions. The same check for each home package manager (node, cargo, uv, bun, pnpm, deno, and any other) says `Node found` or `Cargo found` and shows only that command's version. If that command is missing and its install is already running, the card says `Installing Node` or `Installing Cargo` and does not start another install. If it is missing and nothing is installing, the card says `Installing …`, then `Cargo found` with the version that landed, or `Cargo failed to install`. The card closes, and the next manager starts only after it closes. Core apps have no Stop. `kind: run` curl commands stay a Desktop image layer. Desktop PATH prepends only `$HOME/.local/app-bins` so an app `launch.sh` wins over the installed binary. It does not add Devbox, Nix, Node, or other home package-manager bins. Those bins come from the Devbox shell hook on the home volume. An app with a service has Start, Stop, and Restart, the same three buttons as a non-core docker container, and Logs at `/apps/<id>/logs?role=package`. Restart bumps a count in `running.json` and the supervisor starts the same command again. The log stays after Stop. A package web UI sets `containerPort` and `publish`. Selecting a catalog row stores the model `value`, not the display label (`name · size`). `POST /api/providers/:id/models/pull` `{ model }` (`:id` is `ollama` or `ollama-host`) returns `{ ok, job }` immediately — Pull does not spin. Progress is `GET /api/providers/:id/models/pull` and `activePulls` on `GET /api/providers`. Jobs persist in SQLite `ollama_pull_jobs` (`$BROS_DIR/data/bros.sqlite`) so a Bros/container restart still shows incomplete rows and auto-resumes interrupted `running` jobs. One pull runs at a time per provider (`ollama` vs `ollama-host`); further Pulls are `queued` and wait. That row is inserted at the top with percent/status/bytes and has no Chat switch until the model is installed; Stop aborts the Ollama fetch (or drops a queued job), Resume calls pull again, and the ban icon confirms then stops, drops the job, and tries `DELETE /api/delete` (Ollama may keep incomplete blobs). Docker app compose sets `OLLAMA_NOPRUNE=1`. Host Ollama needs the operator to set the same on the daemon — Bros cannot. User-added names persist in that Ollama provider's `config.customModels` list (SQLite via `upsertProvider`) and appear under **Yours** in the Providers pull menu. Registry errors (including TLS handshake timeout) are shown as returned; one retry on timeout/5xx, never fake success.

OpenAI-compat Chat (`kind: openai`, popular and custom) sends `stream_options: { include_usage: true }`, reads `delta.content` or `delta.reasoning_content`, and adds OpenRouter `HTTP-Referer` + `X-Title: Bros`. Popular Anthropic is `kind: anthropic`: `POST {baseUrl}/messages` with `x-api-key` and `anthropic-version: 2023-06-01`. Keyed health and live model list for Anthropic use the same headers on `GET {baseUrl}/models`. Remote `GET /models` runs only when a key is saved.

## Internal specialist

Packaged GGUF + Modelfile live in git submodule `vendor/bros-model` on a source checkout ([jasenmichael/bros-model](https://github.com/jasenmichael/bros-model)). A release tarball does not ship `vendor/`. Install and `bros update` read the Ollama app's packaged model release and download that release into `$BROS_DATA_DIR/apps/ollama/bros-model` when the local stamp is missing or older. A newer local stamp stays. `bros` start does not download. When the Ollama docker app is up and that GGUF is present (on docker app start and on `/api/providers`), a source checkout copies `models/`, `ollama/`, and `scripts/` onto that directory. Bros bind-mounts the tree at `/bros-model:ro` and runs `bash /bros-model/scripts/install-ollama.sh` inside `bros-ollama` (`ollama create bros`). Desktop and the UI host do not run `ollama create`. Skip if tags already have `bros` and the GGUF size/mtime stamp matches. Missing GGUF: skip quietly; chat still works. `bros update` keeps `data/`, so a model already in the Ollama store survives.

Ollama name `bros` is reserved for the app. First skill is `Label:` chat titles (see Chat) — not the conversation chat model, not listed in Chat or Providers, pull/delete returns 400. Titles always use the trained `bros` model and the short tag. A source checkout copies `vendor/bros-model`. A release uses the Ollama app's packaged model release.

## Gateway

There is no gateway picker and no `/api/gateway`. Chat send is the selected provider and model. Public `/v1` is later (M12-02).

## Tools

Chat is one completion. No tool schemas, no provider Tools switch, and no MCP calls on a send. The `Label:` title call does not get tools. Task skill files stay on disk and are not loaded on a send.

## MCP

Bros stores HTTP MCP servers in SQLite `meta` key `mcp_servers` and toggles them in Settings. Chat does not call them. A later tool engine can.

## Skills

User skills are `$BROS_DIR/data/config/skills/<id>/SKILL.md`, seeded once from `lib/skills/` when missing. `personality` and `rules` load on Chat turns. The rules skill says the model has no tools and must not pretend to browse, read files, or run commands. `data/config/assistant.md` only names those skills. Job skills stay out of the prompt until a later tool engine loads them. The catalog also reads `.cursor/skills`, `.claude/skills`, `.agents/skills`, and `.opencode/skills` under the host home and the working directory when those directories exist. Those copies are read-only. Internal `label`, `task`, and `tasks` live in `$BROS_DIR/data/skills-internal`, seeded from `lib/skills/internal/`, and are not in the catalog. A send does not load `tasks/<mode>.md`. `Label:` titles use the short tag on the trained `bros` model.

## ACP

ACP is not implemented. No route, SDK, or UI. OpenCode or OpenHands as a tool engine is later. Bros does not embed the OpenHands SDK.
