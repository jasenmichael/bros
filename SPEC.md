# SPEC — Bros

**Bros** (**B**oxed **R**untime **O**rchestration **S**ystem) is a Docker-isolated local AI control plane.

## Surfaces

Chat, Agent, Providers, Sidecars, Status, Settings, Docs (from `src/layers/docs`). UI on host port **3055**.

## Chat

`/chat` is a new empty conversation (provider dropdown then model dropdown, centered greeting and composer — no left rail, no empty message well). The composer has a **Voice to text** mic that records in the browser and transcribes through the Whisper addon sidecar. Toggle recording; transcribed text appends to the message and does not auto-send. The provider list omits any provider whose Chat switch on Providers is off. The model dropdown omits models whose per-model Chat switch is off. New chats and provider switches restore the last provider and that provider’s last model from this browser; a saved thread still opens on its stored `modelId`. `/chat/:id` opens a saved thread: messages fill the column and the composer docks at the bottom. Opening a saved thread pins the scroller to the latest turn after render (every `:id` navigation). User turns are visually distinct (right-aligned). The dock label is **New chat**. Previous chats sit under Status as an open, collapsible list. The bottom group is pinned sidecar UIs, then Docs + Settings, then the GitHub footer. Chat is model-only: one streamed completion, no tools.

A conversation is created on the first send, not when opening `/chat`. After the first successful assistant reply, sidecar model **bros** writes a short title from the first user prompt (`Label:`). Later messages do not retitle. If generate fails, keep `New chat` or the first line of the prompt. The model is internal (not listed in Chat or Providers). Recents overflow is Rename and Delete only. Each assistant message stores the `modelId` used for that request; the UI shows `ASSISTANT · <modelId>` under the assistant body. Older rows without a stored model omit the extra text. The assistant meta line keeps duration and token counts on the right when the provider sent them (reload uses the stored row, not the live dropdown). A copy control next to that meta copies the stored raw markdown of the whole reply (fences included). Fenced snippets still copy from `ProsePre`. User turns show copy and edit under the bubble. Edit + resend stops an in-flight stream (same abort as **Stop**), deletes that user turn and every later row (`POST /api/chat/:id/truncate`), then sends the edited text with the same Chat settings prepend/description as a normal send. Title still auto-titles only the first successful reply of a New chat. While a reply is in flight, Send stays the arrow and is disabled until the stream ends. The composer stays editable. Centered **thinking…** shows elapsed time (`1.2s`) and **Stop** until the first assistant token. After tokens start, **Stop** sits on the live assistant meta line. **Stop** aborts the stream. Provider then model sit on the left of the tools row; the selected model's context size sits on the right when Ollama reports it. Assistant and user bodies render as markdown with the same theme visualization as Docs (`.bros-prose` + `ProsePre`). Fenced code snippets include a copy control. Settings Chat fields live in SQLite `meta` (`chat_prepend`, `chat_assistant_description`), not YAML or env. Each user Chat send injects one system message for the description (merged into an existing first system if present) and prefixes the last user text with `{prepend}\n\n` when set. Empty fields are omitted. Stored turns stay as typed. Internal `bros` `Label:` title generate never receives them.

## Agent

`/agent` is a new empty research thread (same provider and model rules as Chat, centered greeting and composer). `/agent/:id` opens a saved agent thread. Agent threads are not Chat: they do not appear under Previous chats, and Chat does not call tools. There is no voice control on Agent.

Each send runs a server loop. Bros implements `web_search` and `web_scrape` against the Firecrawl sidecar (`POST /v2/search`, `POST /v2/scrape`). The model chooses those calls when its API returns `tool_calls` (Ollama and OpenAI-compat). Bros only runs a call the model named, appends the result, and asks again, up to 6 tool calls. A reply with no tool call is the answer. Leftover `kind: anthropic`, or an endpoint that returns 400/422 when `tools` is sent, does not choose: Bros searches the user text, scrapes the top 3 public http(s) hits, and the model writes from that text. Scrape is limited to public http(s) URLs returned by search in that turn. If Firecrawl is stopped, the page says so. Stop aborts the model request and any in-flight Firecrawl call. The stream is SSE (`status`, `token`, `sources`, `stats`, `error`). The stored assistant message is the final markdown plus a short source list, not the raw pages.

## Docs

Shared markdown lives in repo `docs/`. The docs layer (`src/layers/docs`) extends theme (`src/layers/theme`) and owns `/docs` routes. Both `@bros/app` and `@bros/website` `extends` theme and docs. Routes `/docs` and `/docs/*` are the same docs-layer pages in the app UI and the static site — the app does not override them. Theme owns layouts, CSS, and markdown visualization (nav chrome + prose); only nav links differ.

Docs index, dock, and website nav share `DOCS_NAV_TREE` (Start, App, Sidecars, Contribute, API). The tree lists every `docs/` page, including Providers → Ollama + Custom providers and all twelve Popular service pages. App dock **Docs** expands that tree (collapsible; hidden scrollbar). Dashboard…Status stay un-scrolled. Previous chats and Docs each scroll. Website nav is Home plus the same tree. Docs pages show breadcrumbs above the title (Docs / App / Providers / Custom providers).

Website (`src/website`) owns marketing `/` and publishes to GitHub Pages (`baseURL` `/bros/`). Website nav: Home plus the docs directory tree. Landing cards: Chat, Providers, Sidecars, Development. The Bros app owns dashboard `/` plus Chat, Providers, Sidecars, Status, and Settings.

Local docs site: `pnpm docs:dev` → http://127.0.0.1:3056/bros/ ; `pnpm docs:generate` then `pnpm --filter @bros/website preview`.

## Bootstrap

`working_dir`, `data_dir`, and optional `public_url` in YAML:

1. `BROS_CONFIG` exclusive file (install default `~/.config/bros.yml`), or
2. checkout `.config/bros.yml` then `./bros.yml`
3. Env: `BROS_WORKING_DIR`, `BROS_DATA_DIR`, `BROS_PUBLIC_URL`

**`BROS_HOME` (host):** repo checkout when the CLI sits next to `docker-compose.yml` + `sidecars/`. Installed clone is `~/.bros`. `BROS_DIR` is an alias. Override with `BROS_HOME` or `BROS_DIR`. Persistent binds live under `$BROS_HOME/data` (`BROS_HOST_DATA_DIR`):

- `$BROS_HOST_DATA_DIR` → app `/data` (SQLite, additional sidecars, sidecar-repos, logs)
- `$BROS_HOST_DATA_DIR/ollama` → Ollama sidecar `/root/.ollama` (models)
- `$BROS_HOST_DATA_DIR/bros-model` → Ollama sidecar `/bros-model` (packaged specialist tree, read-only)
- `$BROS_HOST_DATA_DIR/ollama-config` → Ollama `/root/.config/ollama`
- `$BROS_HOST_DATA_DIR/openwebui` → Open WebUI data
- `$BROS_HOST_DATA_DIR/opencode` → OpenCode workspace
- `$BROS_HOST_DATA_DIR/opencode-config` → OpenCode `/root/.config/opencode`
- `$BROS_HOST_DATA_DIR/opencode-share` → OpenCode `/root/.local/share/opencode`
- `$BROS_HOST_DATA_DIR/firecrawl-pg` → Firecrawl Postgres
- `$BROS_HOST_DATA_DIR/firecrawl-redis` → Firecrawl Redis
- `$BROS_HOST_DATA_DIR/firecrawl-rabbitmq` → Firecrawl RabbitMQ
- `$BROS_HOST_DATA_DIR/whisper` → Whisper sidecar Hugging Face cache

In-container `BROS_DATA_DIR` stays `/data`. Start does not copy leftover named volumes into those dirs.

All other settings live in SQLite (`bros.sqlite`) and the UI.

## Sidecars

Managed Compose projects **outside** the Bros app stack. Three kinds:

- **Core** — must-run **Ollama** only, from repo `sidecars/ollama`. Always on. No disable env. No Start/Stop/Restart/Autostart UI.
- **Addon** — other shipped packs under repo `sidecars/` (OpenCode, Open WebUI, Firecrawl, Firecrawl UI, Whisper). Optional, **enabled by default**. Disable with `BROS_SIDECAR_OPENCODE=0` / `BROS_SIDECAR_OPENWEBUI=0` / `BROS_SIDECAR_FIRECRAWL=0` / `BROS_SIDECAR_FIRECRAWL_UI=0` / `BROS_SIDECAR_WHISPER=0` or `BROS_SIDECARS_DISABLE=opencode,openwebui,firecrawl,firecrawl-ui,whisper`. Disabled packs stay listed and are not autostarted.
- **Additional** — user-created under `$BROS_HOME/data/sidecars/<id>/` or cloned into `$BROS_HOME/data/sidecar-repos/<name>/` (that tree’s `sidecars/` dir).

Discover merges those four trees. Shipped ids win; custom cannot reuse `ollama`, addon slugs, app routes, or Popular slugs. Compose project name `bros-sc-<id>` on shared external Docker network `bros` (CLI or dockerode create it if missing; core compose does not own it). The Sidecars page has **Core** then one **Addon sidecars** list (shipped + additional). Each card’s source badge is **bros** (shipped), **repo** (git clone), or **custom** (data dir). A refresh icon on each card re-fetches `/api/sidecars` (running/stopped and the rest of that payload). Add sidecar writes the data dir; From a repo clones a git tree. A section with one card uses the wide (horizontal) layout; two or more stay compact in a two-column grid on large screens (mobile is always one wide card per row). Saving an additional sidecar prompts a restart confirm. Git rows have Update (`git pull`) and prompt restart when compose changed.

Every `webui` interface must set `publish` in `sidecar.yml` and map `publish:containerPort` in `docker-compose.yml`. A published `api` is Open the same way (Firecrawl). Pin in nav is only for a published `webui`. Optional `proxy.public: true` on a `webui` enables a Bros path proxy at `/${id}/` only when that UI natively listens under the prefix. That prefix is allowlisted by discovered sidecar id — `/opencode` does not match `/opencode-extra`, and `/chat` stays Bros. Via-tunnel Open/Pin use same-host `/${id}/` (passkey like `/chat`). LAN Open/Pin stay `http://127.0.0.1:<publish>/`, or `http://127.0.0.1:<publish>/${id}/` when the UI listens under that path. No shipped pack opts in today: `ghcr.io/anomalyco/opencode` 1.18.30 ignores `OPENCODE_SERVER_BASE_PATH`, rejects `--base-path`, and serves `/` (assets at `/assets`). Compose still sets that env for when upstream ships base-path. Open WebUI, Ollama, and other packs without `proxy.public` stay LAN-only. Sidecars copy lists host publish URLs and Docker DNS `http://<service>:<containerPort>` for `api` interfaces. Compose-app Bros → sidecar APIs always use that Docker DNS on network `bros` (Ollama `http://ollama:11434`, Whisper `http://whisper:8000`), including when the browser is on `public_url`. Host Node (`pnpm app:dev`) uses `http://127.0.0.1:<publish>` (`BROS_OLLAMA_PORT` / `BROS_WHISPER_PORT` overrides). Other containers still use internal DNS. Host **publish** ports **3000** and **8080** are forbidden. Env overrides (`BROS_OLLAMA_PORT`, `BROS_OPENCODE_PORT`, `BROS_OPENWEBUI_PORT`, `BROS_FIRECRAWL_PORT`, `BROS_FIRECRAWL_UI_PORT`, `BROS_WHISPER_PORT`) are escape hatches for host publish / host Node.

Bros always `compose up` each sidecar on its **publish** port. Start fails if that port is already taken. Occupancy of the upstream default (Ollama 11434) does **not** skip the Bros sidecar (publish **11435**).

**Host Ollama** (Chat/Providers) is a second built-in provider (`ollama-host`). Settings **Enable host Ollama** (SQLite `meta.enable_host_ollama`) is **off by default**. Off omits the row from `GET /api/providers`, the Chat picker, and the Providers page; `/api/providers/ollama-host/*` returns 404. The SQLite provider row stays so Chat-enable and `config.disabledModels` survive. Bros never starts the host daemon. When on, live scan finds one daemon: manual SQLite `host_probe_port` is exclusive (no silent fallback); else probe default **11434** first via `dockerHostCandidates()` (`host.docker.internal` / `BROS_HOST_GATEWAY` from the app container, `127.0.0.1` on host Node). Skip if that port is sidecar publish **11435** or `bros-sc-ollama`. Then published host ports on running Docker Ollama containers (image `ollama/ollama` or name containing `ollama`; skip project/name `bros-sc-ollama` and publish **11435**). Then leftover `/proc/net/tcp`+`tcp6` LISTEN ports (host Node) and other published ports. In the app container, host `/proc` is invisible — still probe host-gateway **11434**, not only the container listen table. Verify with `GET /api/version` JSON `{ version }`. Skip sidecar publish **11435** and any port whose `publishedPortOwner` project is the Bros Ollama sidecar. First `GET /api/version` hit wins. Do not HTTP-probe 1–65535 on every list. `POST /api/providers/ollama-host/scan` busts the 30s cache.  No extra npm deps (dockerode + `/proc`). Sidecar Ollama stays `ollama` at DNS `http://ollama:11434` (host publish **11435**). The Compose app never uses the sidecar publish port for Chat/Providers/STT (from inside the container `127.0.0.1` is the Bros process). When the app process is on the host (`pnpm app:dev`), Chat/Providers use `http://127.0.0.1:11435` for the sidecar (`BROS_OLLAMA_PORT` if set) and `http://127.0.0.1:<probe>` for host Ollama — not Docker DNS (`ollama`, `host.docker.internal`). Chat picks a provider, then a model, in order: sidecar, host (if enabled), Popular services (fixed catalog), then custom — omitting any provider whose Chat switch is off, and omitting models stored in that provider’s `config.disabledModels`. If the current Chat model belongs to a provider the user then disables, Chat falls back to the next enabled provider. `modelId` is `providerId/model` (`ollama/llama3.2`, `ollama-host/llama3.2`, `openai/gpt-4o-mini`, `my-proxy/qwen2.5`). GPU / pull into `$BROS_HOME/data/ollama` is the sidecar; host pull/chat use the host Ollama disk (no Bros disk-fit check). Popular services and custom providers are OpenAI-compatible (base URL + optional key + model names), not a paid catalog. Keys live in SQLite only (no `OPENAI_API_KEY` env bootstrap).

`bros start` (and `pnpm dev`) remove legacy `forgebox-sc-*` containers before up. `bros stop` and interactive Ctrl+C stop all `bros-sc-*` sidecars, then the core stack — so sidecars never stay orphaned beside a stopped app. First start also brings up sidecar Ollama and installs the internal `bros` model when the packaged GGUF is present (see Internal specialist).

Keep product language **sidecar** / **Sidecars** (routes `/sidecars`, APIs `/api/sidecars`, file `sidecar.yml`).

## Status

`/status` reports Bros app, Docker, disk, GPU, host Tunnel, and each sidecar’s port/state/error plus autostart/pin. `/api/status` also includes `enableHostOllama` and `containers` (every Bros-managed Docker container: app `bros` plus each `bros-sc-*` service, including stopped). Dashboard widget grid is Bros, Docker, disk, GPU, **Ollama** (sidecar + host providers, Details → `/providers`), and Tunnel — no Sidecars summary card. The Ollama card shows sidecar publish `http://127.0.0.1:11435/` (copy) and, when Settings **Enable host Ollama** is on, a Host line with that daemon’s URL. Host is omitted when the flag is off. A **Bros services** section lists those containers grouped by app / sidecar pack (state + published ports). Sidecar rows sit in a later **Sidecar snippets** section (publish port only; not host Ollama) and link to Status (and Logs when a container exists). Home does not render the full Status table. Sidecar Ollama recovery also sets `ollamaRestartNotice` on this payload (toast, not a Status table row).

Dashboard also has a **Tunnel** card for a **host** `cloudflared` process. It is not a sidecar. A non-empty `public_url` in bootstrap YAML is the enable + hostname signal: `bros` / helper startup starts a **named** tunnel (`cloudflared tunnel create`, `cloudflared tunnel route dns <id> <hostname>` which creates a CNAME to `<id>.cfargotunnel.com`, then `cloudflared tunnel --config $BROS_HOME/data/tunnel/config.yml run bros`). `config.yml` has hostname ingress, catch-all `http_status:404`, `protocol: http2`, and `edge-ip-version: 4`. Override with `BROS_TUNNEL_PROTOCOL` (`http2` / `quic` / `auto`) and `BROS_TUNNEL_EDGE_IP_VERSION` (`4` / `6` / `auto`). Quick `*.trycloudflare.com` is only used when `public_url` is unset and the card is turned on. If start fails, `status.json` `error` is shown on the Dashboard card and Status. `route dns` “already exists” is success. If `route dns` times out on Cloudflare’s API, the named tunnel still starts and Dashboard shows the CLI warning plus the expected CNAME (not a leftover REST `PUT /zones/.../tunnels/.../routes` as the only message). If the logged-in Cloudflare account does not own the hostname’s DNS zone (`tunnel route dns` CNAME mismatch or zone error), the tunnel does not start and that reason is shown. Runtime connection errors after the last successful register (for example QUIC idle timeout) are shown even while the process is up. Turning the card off stops the process until the next `./bros` / helper start.

A request is **via-tunnel** when any of `cf-ray`, `cf-connecting-ip`, or `cf-visitor` is present, `cdn-loop` contains `cloudflare`, or the request Host matches `public_url`, optional `BROS_TUNNEL_HOST`, or the last advertised hostname. `/api/status` includes `viaTunnel`, `tunnelHost`, and `tunnel`. While via-tunnel, stop is refused (API 403) and the Dashboard toggle is disabled so the session cannot lock itself out. Start remains allowed. Chat, Providers, and Whisper STT keep working: the browser talks only to Bros `/api/*` on that hostname; Bros talks to sidecars on Docker network `bros`. Sidecar Open/Pin stay host-local except `proxy.public` webuis, which share the Bros hostname and passkey (see Sidecars). No shipped pack sets `proxy.public` today.

`pnpm dev` behind the tunnel must keep Vite client modules bootable. Vite serves one `.css` path as `text/css` (`<link>`) or `text/javascript` (JS import). Cloudflare caches that path (query string ignored), so a stylesheet body is reused for the module import and Nuxt never hydrates (Unlock does nothing). Dev rewrites CSS module imports to `/_nuxt/bros-mod/…*.js` and sends `CDN-Cache-Control: no-store` on Vite `/_nuxt` assets. Production hashed CSS is not affected.

## Auth

Shared passcode. Source of truth is plaintext file `{dataDir}/passkey` (in Docker: `/data/passkey`). On startup Bros creates the file if missing and prints the key to logs. Settings / setup update the file. Session cookie `bros_session` (HttpOnly, SameSite=Lax, Path=/; host-only; Secure on HTTPS including the Cloudflare tunnel, not on local HTTP). `/status` is gated like other app pages. Via-tunnel stop-lock does not apply to login.

## Sidecar kinds

**Core:** `ollama` (Bros publish **11435**, container 11434; host install stays **11434**). Sidecars / Status / Home have no Start, Stop, or Restart for it. Autostart cannot be turned off. `POST /api/sidecars/ollama/start`, `…/stop`, and `…/restart` return 400. Host Ollama (`ollama-host`) is not a sidecar and is not locked. A server health check (compose process down, or `GET /api/version` fail) restarts the sidecar container internally — not for a single slow pull. `/api/status` and `/api/sidecars` expose `ollamaRestartNotice` `{ recoveredAt, lastRestartReason }` once per recovery; the app toasts with Nuxt UI `useToast`.

**Addon:** `opencode` (publish **4097**), `openwebui` (publish **3080** → container 8080), `firecrawl` (publish **3002**, scrape API; Playwright 3000 stays internal), `firecrawl-ui` (publish **3081** → container 8080), `whisper` (publish **8090** → container 8000, Chat STT; not a Chat provider). Start/Stop/Restart, autostart, and logs stay in the UI.

**Additional:** user and git sidecars. Same controls as addons. Cloudflare tunnel is a host `cloudflared` process, not a sidecar.

## Providers

Providers (`/providers`) lists **Ollama** (sidecar, then host when Settings enable host Ollama is on), **Popular services** (12 always-listed OpenAI-compat cloud cards), then **Custom providers**. Sidecar and popular cards always appear; host appears only when that Settings toggle is on. Display titles are **Ollama (core)** and **Ollama (host port:N)** (live probe/override; stored SQLite names stay `Ollama (core)` / `Ollama (host)` without a port). Row health is **Ready**, **Need an API key**, **Invalid key**, or **Unreachable** — never running/stopped (those words are sidecar process state on Status). Ready means a live probe succeeded (Ollama version/tags, or keyed `GET /models` with the saved key). A non-empty key field alone is not Ready. Rows show host:port (`127.0.0.1:11435` for sidecar publish, host probe/override for host, API host for popular/custom) — not the provider id — with copy. Custom still opens that endpoint in a new tab. Ollama sidecar and host rows keep copy only (no external-link). Popular rows open the provider console/keys page (`siteUrl` on the preset), not the API host. Both Ollama cards start collapsed (no pull or installed-model list until the user opens one). Selecting a different Ollama card expands pull and the installed-model list on that card (the other collapses). The chevron or a second click on the already-open card collapses the panel; the card stays selected for the session. Each provider row has a **Chat** switch (label above the switch) that only removes that provider from the Chat picker — it does not stop the sidecar, host Ollama, or any other provider. Ollama sidecar and host default Chat **on**; Popular services and custom providers default Chat **off**. Keyed Chat can turn on only after Bros saves a key and the health probe succeeds; Chat-on with no key is invalid and is turned off on load. User can still turn Chat off without deleting the key. Internal specialist `bros` still uses sidecar Ollama when that provider is off for Chat. Ollama and Popular cards expand in-place: installed or listed models first, then settings under that list (sidecar GPU, host port override, popular API key + optional model list). Each installed Ollama model row has a Chat switch (default on; off stores the name in that provider’s `config.disabledModels` and hides it from that provider’s Chat picker) and a compact red ban icon. Delete needs an Are you sure? confirm that names the model; cancel does nothing. Popular catalog rows (and custom lists that share that UI) have the same Chat switch and the same `config.disabledModels` store; they have no delete — Bros does not own the remote catalog. The models textarea is a seed/fallback, not an allowlist. No settings cog on Ollama or Popular. GPU never appears for host/popular/custom. Popular settings have no Delete and no pull. Custom providers still use a settings cog (UModal). Custom providers are OpenAI-compatible (base URL, optional key, model names); Add custom lives under that heading. Popular slugs are reserved (cannot delete, cannot reuse as a custom id). Heading is never “Paid providers”.

Recommended pulls are official (and verified community) Ollama tags whose on-disk size is **≤ 16 GB**. `qwen3-coder:14b` is not a library tag (official coder is `:30b` / `:480b`); use `freehuntx/qwen3-coder:14b` or `qwen2.5-coder:14b`. 30B tags (~19 GB) stay in the Ollama list, not Recommended.

Any valid Ollama name can be typed and pulled (`name:tag` or community `owner/name:tag`). The catalog dropdown opens only while the pull input is empty; a typed or selected valid name closes it and enables Pull (click the input again to reopen and pick something else). Selecting a catalog row stores the model `value`, not the display label (`name · size`). `POST /api/providers/:id/models/pull` `{ model }` (`:id` is `ollama` or `ollama-host`) returns `{ ok, job }` immediately — Pull does not spin. Progress is `GET /api/providers/:id/models/pull` and `activePulls` on `GET /api/providers`. Jobs persist in SQLite `ollama_pull_jobs` (`$BROS_HOME/data/bros.sqlite`) so a Bros/container restart still shows incomplete rows and auto-resumes interrupted `running` jobs. One pull runs at a time per provider (`ollama` vs `ollama-host`); further Pulls are `queued` and wait. That row is inserted at the top with percent/status/bytes and has no Chat switch until the model is installed; Stop aborts the Ollama fetch (or drops a queued job), Resume calls pull again, and the ban icon confirms then stops, drops the job, and tries `DELETE /api/delete` (Ollama may keep incomplete blobs). Sidecar compose sets `OLLAMA_NOPRUNE=1`. Host Ollama needs the operator to set the same on the daemon — Bros cannot. User-added names persist in that Ollama provider's `config.customModels` list (SQLite via `upsertProvider`) and appear under **Yours** in the Providers pull menu. Registry errors (including TLS handshake timeout) are shown as returned; one retry on timeout/5xx, never fake success.

OpenAI-compat Chat (`kind: openai`, popular and custom) sends `stream_options: { include_usage: true }`, reads `delta.content` or `delta.reasoning_content`, and adds OpenRouter `HTTP-Referer` + `X-Title: Bros`. Native Anthropic stream stays for leftover `kind: anthropic` rows; popular Anthropic is seeded as `kind: openai`. Remote `GET /models` runs only when a key is saved.

## Internal specialist

Packaged GGUF + Modelfile live in git submodule `vendor/bros-model` ([jasenmichael/bros-model](https://github.com/jasenmichael/bros-model)). When the Ollama sidecar is up (`startSidecar('ollama')` and `/api/providers`), Bros `ensureInternalBrosModel` copies `models/`, `ollama/`, and `scripts/` onto `$BROS_HOST_DATA_DIR/bros-model`, bind-mounts that tree at `/bros-model:ro`, and runs `bash /bros-model/scripts/install-ollama.sh` inside `bros-sc-ollama` (`ollama create bros`). Skip if tags already have `bros` and the GGUF size/mtime stamp matches. Missing GGUF: log once, skip; chat still works.

Ollama name `bros` is reserved for the app. First skill is `Label:` chat titles (see Chat) — not the conversation chat model, not listed in Chat or Providers, pull/delete returns 400. Typical model update: bump the pinned submodule, then release a new Bros version.
